# Стратегии сэмплирования

Сэмплер влияния объединяет значения, переданные непустой выборкой источников в точке запроса.
Поле определяет, какие источники попадут в сэмплер, а сэмплер превращает их в одно исходное
значение. Поэтому выбор стратегии меняет форму и непрерывность поля, а не только его
производительность.

Встроенные стратегии реализуют
<xref:Akeldov.Math.Spatial2D.Fields.IInfluenceSampler`2>.

## Выбор стратегии

| Стратегия | Встроенный сэмплер | Результат | Использование веса |
|---|---|---|---|
| Ближайший источник | <xref:Akeldov.Math.Spatial2D.Fields.NearestInfluenceSampler`2>, <xref:Akeldov.Math.Spatial2D.Fields.NearestFloatInfluenceSampler`1> и <xref:Akeldov.Math.Spatial2D.Fields.NearestIntInfluenceSampler`1> | Значение геометрически ближайшего источника; границы между источниками резкие | Игнорируется |
| Обратно-взвешенное по расстоянию | <xref:Akeldov.Math.Spatial2D.Fields.InverseDistanceWeightedFloatSampler`1> | Плавная вещественная смесь всех выбранных источников | Умножает вклад источника, обратно пропорциональный расстоянию |
| Барицентрическая | <xref:Akeldov.Math.Spatial2D.Fields.BarycentricFloatSampler`1> и <xref:Akeldov.Math.Spatial2D.Fields.BarycentricIntSampler`1> | Линейная интерполяция или экстраполяция вдоль отрезка или по треугольнику | Влияет на порядок кандидатов при наличии более трёх источников, но не на коэффициенты интерполяции |

Используйте ближайший источник для категорий, областей владения, масок и значений, которые нельзя
смешивать. Обратно-взвешенное сэмплирование подходит для плавных полей, где должен участвовать
каждый выбранный источник. Барицентрическое сэмплирование создаёт кусочно-линейное поле,
определяемое локальной геометрией источников.

## Общие данные примеров

Типы сэмплера и значения источника входят в обобщённый контракт. Для вещественных точечных
источников все три стратегии можно заменять без изменения типа поля. В примерах ниже используем
три источника с одинаковым весом `1` и одну точку запроса `P(4, 3)`:

```csharp
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Fields;
using Akeldov.Math.Spatial2D.Imaging;
using Akeldov.Math.Spatial2D.Rasterization;

var sources = new[]
{
    new FloatPointInfluenceSource(1f, new PointXY(0f, 0f), 0f),     // A
    new FloatPointInfluenceSource(1f, new PointXY(10f, 0f), 100f),  // B
    new FloatPointInfluenceSource(1f, new PointXY(0f, 10f), 50f)    // C
};

var query = new PointXY(4f, 3f);
var geometry = new RasterGeometry(
    new PointXY(0f, 0f),
    new VectorXY(10f, 10f),
    new VectorXYInt(400, 400));
```

Каждый следующий фрагмент использует эти `sources`, `query` и `geometry`. Источники передаются полю напрямую,
без пространственного индекса: все три участвуют в каждом запросе, поэтому сравнение показывает
именно различия сэмплеров.

Все PNG ниже — прямой результат `RasterizeHeatMap(geometry)` и `SaveAsPng`, вызванных в примерах.
Библиотека вычисляет поле в центрах ячеек сетки `400 × 400` в квадрате `0 ≤ x, y ≤ 10`.
Используется её стандартная температурная шкала: синий соответствует `0`, зелёный — `50`,
красный — `100`. Ось `y` направлена вверх: источник `A` находится в нижнем левом углу,
`B` — в нижнем правом, `C` — в верхнем левом. Файлы сохраняются в рабочую директорию приложения.

## Поведение ближайшего источника

Стратегия запрашивает у каждого выбранного источника его `InfluenceSample` и возвращает значение
с наименьшим геометрическим `Distance`. При равных расстояниях побеждает источник, который раньше
стоит в выборке. Вес источника не участвует в сравнении.

Обобщённый `NearestInfluenceSampler<TSource, TValue>` работает с произвольными типами значений,
включая `bool` и пользовательские категории. Вещественная и целочисленная версии предоставляют
удобные числовые специализации с тем же поведением.

### Пример: зоны ближайшего источника

```csharp
var nearestField = new FloatPointInfluenceField(
    new NearestFloatInfluenceSampler<FloatPointInfluenceSource>(),
    sources);

float nearestValue = nearestField.Sample(query); // 0
nearestField.RasterizeHeatMap(geometry).SaveAsPng("sampling-nearest.png");
```

Расстояние от `P` до `A` равно `5`, до `B` — `√45 ≈ 6.71`, до `C` — `√65 ≈ 8.06`.
Ближе всего источник `A`, поэтому результат равен его значению `0`.

На карте получаются три однотонные области со значениями `0`, `50` и `100`.
При пересечении границы ближайший источник меняется, и значение скачком переходит в другую
категорию. Такой выбор подходит, например, для зон владения или назначения ближайшего датчика.

## Обратно-взвешенное сэмплирование

Для каждого выбранного источника, расстояние до которого превышает геометрический допуск,
сэмплер вычисляет:

```text
вес вклада = вес источника / расстояние
результат = сумма(значение источника * вес вклада) / сумма(вес вклада)
```

Поэтому близкие источники вносят больший вклад, а увеличение веса источника пропорционально
усиливает его влияние. Каждый источник должен возвращать конечный положительный вес. Если точка
запроса практически совпадает с источником, его значение возвращается сразу, что предотвращает
неустойчивое деление.

Обратно-взвешенное сэмплирование является глобальным для полученного списка источников. Уменьшение
этого списка на этапе выборки поля превращает смешивание в локальное и может заметно изменить
результат.

### Пример: плавное поле по трём измерениям

```csharp
var weightedField = new FloatPointInfluenceField(
    new InverseDistanceWeightedFloatSampler<FloatPointInfluenceSource>(),
    sources);

float weightedValue = weightedField.Sample(query); // Примерно 44.6176
weightedField.RasterizeHeatMap(geometry).SaveAsPng("sampling-inverse-distance-weighted.png");
```

При одинаковом весе источников коэффициенты вклада в точке `P` равны `1/5`, `1/√45` и `1/√65`:

```text
f(P) = (0/5 + 100/√45 + 50/√65) / (1/5 + 1/√45 + 1/√65)
     ≈ 44.62
```

Источник `A` остаётся ближайшим, но значения `B` и `C` тоже участвуют в результате.
На карте виден непрерывный переход между измерениями; в точках самих источников поле возвращает
их значения. Это удобно, например, для восстановления распределения температуры по датчикам.

## Поведение барицентрической стратегии

Барицентрические сэмплеры адаптируются к числу выбранных источников:

| Число источников | Поведение |
|---|---|
| Один | Возвращает значение этого источника. |
| Два | Интерполирует вдоль прямой через точки источников и экстраполирует за пределами отрезка. Для совпадающих точек возвращает первое значение. |
| Три | Использует барицентрические координаты треугольника источников. Для вырожденного треугольника переходит к первым двум источникам. |
| Больше трёх | Ищет треугольники среди ближайших эффективных кандидатов. Предпочитает треугольник, содержащий точку запроса, затем треугольник с наименьшим штрафом за нахождение снаружи; если подходящего треугольника нет, использует двух ближайших кандидатов. |

Эффективное расстояние до кандидата равно геометрическому расстоянию, делённому на вес источника
с небольшим положительным нижним пределом делителя. После выбора отрезка или треугольника
коэффициенты интерполяции зависят только от точек и значений источников.

По умолчанию сэмплер рассматривает не более `DefaultMaxCandidateSamples` кандидатов. Увеличьте
предел, если в выборе должно участвовать более широкое окружение источников:

```csharp
var sampler =
    new BarycentricFloatSampler<FloatPointInfluenceSource>(
        maxCandidateSamples: 12);
```

Предел должен быть не меньше трёх. Поиск треугольников имеет кубическую сложность относительно
числа кандидатов, поэтому небольшая локальная выборка предпочтительнее избыточно большого
предела. `BarycentricIntSampler` использует те же геометрические правила и округляет результат
интерполяции до ближайшего целого.

### Пример: линейное изменение внутри треугольника

```csharp
var barycentricField = new FloatPointInfluenceField(
    new BarycentricFloatSampler<FloatPointInfluenceSource>(),
    sources);

float barycentricValue = barycentricField.Sample(query); // 55
barycentricField.RasterizeHeatMap(geometry).SaveAsPng("sampling-barycentric.png");
```

Точка `P(4, 3)` лежит внутри треугольника `ABC`. Её барицентрические коэффициенты для `A`, `B`
и `C` равны `0.3`, `0.4` и `0.3`:

```text
P = 0.3 * A + 0.4 * B + 0.3 * C
f(P) = 0.3 * 0 + 0.4 * 100 + 0.3 * 50 = 55
```

Внутри треугольника получается линейное поле `f(x, y) = 10x + 5y`.
Оно подходит, например, для интерполяции высоты или другого скаляра по вершинам треугольной сетки.
В этом примере все запросы используют один треугольник.

Вне треугольника сэмплер экстраполирует ту же плоскость, а `FloatPointInfluenceField` ограничивает
результат диапазоном `[0, 100]`. Поэтому правый верхний угол карты однотонный: в точке `(10, 10)`
исходный результат `150` превращается в `100`.

## Диапазоны результата и некорректные данные

Сэмплеры возвращают исходный математический результат. Экстраполяция по прямой или треугольнику
может выйти за диапазон значений источников. Ограниченные вещественные и целочисленные поля
ограничивают результат своими публичными `Min` и `Max`, а обобщённый
`InfluenceField<TSource, TValue>` этого не делает.

Каждый сэмплер требует непустой список источников без `null` и точку запроса с конечными
координатами. Отдельные источники отвечают за корректность своих `InfluenceSample`, а
обратно-взвешенная стратегия дополнительно требует конечный положительный вес.

Полный конвейер от источников до поля описан на странице [Поля](../fields.md). Практические
примеры приведены в руководстве
[Построение карты влияния](../../how-to-guides/fields/build-an-influence-map.md) и в учебнике
[Создание карты влияния](../../tutorials/building-an-influence-map/index.md).
