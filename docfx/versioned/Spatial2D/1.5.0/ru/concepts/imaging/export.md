# Экспорт

Экспорт кодирует цветовой растр в изображение PNG или BMP. Методы расширения
<xref:Akeldov.Math.Spatial2D.Imaging.RasterPngExtensions> и
<xref:Akeldov.Math.Spatial2D.Imaging.RasterBmpExtensions> принимают
<xref:Akeldov.Math.Spatial2D.Rasterization.IRaster`1>, поэтому сохранять можно и `Raster<TColor>`,
и `SpatialRaster<TColor>`. Экспорт читает существующие пиксели, не изменяя их.

## Выбор формата изображения

| Тип ячейки растра | `SaveAsPng` | `SaveAsBmp` |
|---|---|---|
| `Gray8BitColor` | 8-битные оттенки серого | 8-битные индексированные оттенки серого |
| `Gray16BitColor` | 16-битные оттенки серого | Нет перегрузки |
| `RGBA8BitColor` | 8 бит на канал RGBA | 32-битный BGRA |
| `RGBA16BitColor` | 16 бит на канал RGBA | Нет перегрузки |

PNG сохраняет выбранную глубину каналов и альфу RGBA. При сохранении 16-битного цветового растра
каналы не преобразуются в 8-битные. BMP требует один из двух поддерживаемых 8-битных цветовых
типов; для экспорта растра большей точности в BMP явно преобразуйте значения.

Кодирование определяется методом экспорта, а не расширением имени файла. Используйте подходящее
расширение `.png` или `.bmp`, чтобы другим программам было проще определить формат.
Типы пикселей и диапазоны каналов описаны в разделе [Цветовые растры](../rasterization/color-rasters.md).

## Подготовка числовых значений

Числовые и булевы растры перед экспортом нужно явно преобразовать в поддерживаемый цветовой тип.
`MapValues` создаёт новый цветовой буфер. В булевой маске можно отобразить `false` в чёрный,
а `true` — в белый. Для высот и расстояний сначала выберите физический диапазон, затем
нормализуйте его в `[0, 1]`.

`FromNormalized` ограничивает диапазон и округляет каналы. Значения вне выбранного диапазона
теряют информацию, а диапазон нулевой ширины требует отдельного правила преобразования.
Сохраняйте числовой растр, если последующим вычислениям нужны исходные значения.

## Сохранение в файл или поток

Пример переводит высоты из `[0, 10]` в оттенки серого, записывает 16-битный PNG и создаёт
8-битное превью BMP. Тот же PNG можно закодировать в поток памяти:

```csharp
using System.IO;
using System.IO.Compression;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Imaging;
using Akeldov.Math.Spatial2D.Rasterization;

var heights = new FloatRaster(
    new VectorXYInt(2, 2), new[] { 0f, 2.5f, 5f, 10f });
Raster<Gray16BitColor> image = heights.MapValues(
    height => Gray16BitColor.FromNormalized(height / 10f));
image.SaveAsPng("heights.png");

Raster<Gray8BitColor> preview = heights.MapValues(
    height => Gray8BitColor.FromNormalized(height / 10f));
preview.SaveAsBmp("heights.bmp");

using var stream = new MemoryStream();
image.SaveAsPng(stream, CompressionLevel.Fastest);
byte[] pngBytes = stream.ToArray();
```

Перегрузки с путём создают или перезаписывают целевой файл. Перегрузки с потоком записывают
данные в доступный для записи поток и оставляют его открытым; временем жизни управляет
вызывающий код. Перед чтением изображения из потока с поддержкой позиционирования
установите `Position` в ноль.

## Сжатие PNG и пространственные метаданные

По умолчанию PNG использует `CompressionLevel.Optimal`. Перегрузки с `CompressionLevel`
позволяют выбрать другой режим, например `Fastest`. Сжатие влияет на затраты кодирования
и размер файла, но не на пиксели или точность каналов: сжатие PNG выполняется без потерь.

Изображение содержит разрешение и цвета пикселей, но не `RasterGeometry`, мировые границы
или правило преобразования чисел в цвета. Сохраняйте эту информацию отдельно, если нужно
связать изображение с мировыми координатами или физическими величинами. Экспорт не удаляет
геометрию пространственного растра из памяти — она лишь не записывается в изображение.
