# Импорт

<xref:Akeldov.Math.Spatial2D.Imaging.RasterImageLoader> загружает PNG и BMP в новые изменяемые
буферы `Raster<TColor>`, принадлежащие вызывающему коду. Формат изображения и тип пикселей
выбираются явно через имя метода. Каждый метод принимает путь к файлу или доступный для чтения поток.

## Выбор загрузчика

| Метод | Поддерживаемый вход | Результат |
|---|---|---|
| `LoadGray8FromPng` | PNG с 8-битными оттенками серого без альфы | `Raster<Gray8BitColor>` |
| `LoadGray16FromPng` | PNG с 16-битными оттенками серого без альфы | `Raster<Gray16BitColor>` |
| `LoadRgba8FromPng` | PNG с 8-битными каналами RGBA | `Raster<RGBA8BitColor>` |
| `LoadRgba16FromPng` | PNG с 16-битными каналами RGBA | `Raster<RGBA16BitColor>` |
| `LoadGray8FromBmp` | Несжатый индексированный 8-битный BMP с серой палитрой | `Raster<Gray8BitColor>` |
| `LoadRgba8FromBmp` | Несжатый индексированный 8-битный BMP с любой палитрой или 32-битный BGRA BMP | `Raster<RGBA8BitColor>` |

Тип цвета и глубина каналов PNG должны соответствовать выбранному методу. Загрузчик не
преобразует автоматически оттенки серого в RGBA или 16-битные каналы в 8-битные. Индексированный
PNG, RGB PNG без альфы и серый PNG с альфой не поддерживаются. Поддерживаются все фильтры строк
PNG и чересстрочная развёртка Adam7; значения сохраняются без преобразования цветового пространства.

BMP может хранить строки снизу вверх или сверху вниз и должен использовать информационный
заголовок Windows. Индексы палитры преобразуются в цвета, а не сохраняются в ячейках.
Цвета палитры непрозрачны; четвёртый байт 32-битного пикселя BGRA сохраняется как альфа.
Загрузчиков для 24-битного или сжатого BMP нет.

Сначала используйте подходящий загрузчик, затем `MapValues` для явного преобразования между
поддерживаемыми типами ячеек. Диапазоны каналов и точность описаны в разделе
[Цветовые растры](../rasterization/color-rasters.md).

## Загрузка из файла или потока

В примере `drawing.png` должен содержать 8-битные пиксели RGBA, например изображение,
сохранённое из `SpatialRaster<RGBA8BitColor>` методом `SaveAsPng`:

```csharp
using System.IO;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Imaging;
using Akeldov.Math.Spatial2D.Rasterization;

Raster<RGBA8BitColor> image = RasterImageLoader.LoadRgba8FromPng("drawing.png");

using var stream = File.OpenRead("drawing.png");
Raster<RGBA8BitColor> fromStream = RasterImageLoader.LoadRgba8FromPng(stream);

var geometry = new RasterGeometry(
    new PointXY(0f, 0f), new VectorXY(80f, 50f), image.Resolution);
var spatial = new SpatialRaster<RGBA8BitColor>(geometry, image.Values);
spatial.DrawText("Imported", new PointXY(10f, 40f), height: 3f);
spatial.SaveAsPng("annotated.png");
```

Файловые перегрузки сами открывают и закрывают входной поток. Потоковые перегрузки начинают
с текущей позиции и оставляют поток открытым; возможность позиционирования не требуется.
Перед чтением потока памяти, только что использованного для экспорта, установите его `Position`
в ноль. Чтение PNG заканчивается после блока `IEND`; чтение BMP потребляет размер,
указанный в заголовке файла.

## Ориентация, владение данными и пространственные границы

В загруженном растре Y увеличивается от нижней строки изображения: `image[0, 0]` — нижний левый
пиксель. Значения хранятся по строкам; плоский индекс равен `y * Resolution.X + x`. Массив пикселей
и индексаторы позволяют менять значения. Отдельные вызовы загрузки создают независимые буферы.

Изображение предоставляет разрешение и цвета, но не восстанавливает `RasterGeometry` или
правило преобразования чисел в цвета при экспорте. Пример явно задаёт мировые границы:
прямоугольник `80` на `50` мировых единиц определяется приложением, а не данными PNG.

Оборачивание `image.Values` в `SpatialRaster<TColor>` сохраняет тот же массив: рисование через
`spatial` меняет и `image`. Для независимых пикселей скопируйте массив перед созданием оболочки.
Контракт геометрии описан в разделе [Пространственные растры](../rasterization/spatial-rasters.md),
а операции над загруженным пространственным цветовым растром — в разделе [Рисование](drawing.md).

## Неподдерживаемые или некорректные данные

Неподдерживаемое кодирование и несовпадение формата пикселей PNG вызывают `NotSupportedException`.
Повреждённые, обрезанные или слишком большие данные изображения вызывают `InvalidDataException`.
Недоступный для чтения поток вызывает `ArgumentException`; доступ к файлу также может
завершиться обычными исключениями ввода-вывода. Выбор другого метода сам по себе не преобразует
неподдерживаемое кодирование источника.

Сохранение результата описано в разделе [Экспорт](export.md), а цвета и смешивание —
в разделе [Изображения](../imaging.md).
