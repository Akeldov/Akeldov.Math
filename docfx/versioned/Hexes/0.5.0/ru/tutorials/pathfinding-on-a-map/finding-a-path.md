# Поиск пути

В этой части руководства вы найдёте самый дешёвый маршрут от `start` до `goal`.
`FindShortestPath` рассматривает только шесть соседей с общим ребром и использует алгоритм
Дейкстры.

## Запуск поиска

Замените диагностику воды в конце `Program.cs` следующим кодом:

```csharp
HexPath? path = transferCosts.FindShortestPath(start, goal);

if (path is null)
{
    Console.WriteLine("Маршрут не найден.");
    return;
}

Console.WriteLine($"Общая стоимость: {path.TotalCost}");
Console.WriteLine($"Посещено гексов: {path.HexIndexes.Count}");

foreach (VectorXYInt index in path.HexIndexes)
{
    Console.WriteLine(index);
}
```

Ожидаемый результат:

```text
Общая стоимость: 8
Посещено гексов: 9
(0, 2)
(1, 2)
(1, 3)
(2, 4)
(3, 4)
(4, 4)
(5, 4)
(5, 3)
(6, 2)
```

Прямой путь пересекает лес и стоит дороже. Полученный маршрут делает восемь шагов по равнине
вдоль нижнего края, поэтому его общая стоимость равна `8`. Существует равноценный верхний путь:
логика приложения должна зависеть от минимального `TotalCost`, а не от выбора одного из
равноценных маршрутов.

<xref:Akeldov.Math.Hexes.Pathfinding.HexPath.HexIndexes> включает обе конечные точки и предоставляет
семантический результат как доступную только для чтения последовательность. `TotalCost` содержит
сумму переходов между соседними индексами.

Оставьте `path` в области видимости и переходите к разделу
[Обработка недостижимой цели](handling-an-unreachable-target.md).
