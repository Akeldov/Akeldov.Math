# Хроматизация

Хроматизация присваивает каждому индексу гекса один из трёх классов: `0`, `1` или `2`. Это
правильная раскраска решётки: любые два гекса с общим ребром получают разные классы, а три гекса
с общей вершиной содержат все три класса.

Класс зависит только от логического индекса и раскладки. Значения карты, её конечные границы,
радиус и начало мировых координат не влияют на результат. Поэтому одна и та же классификация
может использоваться для независимых проходов по карте и для устойчивого порядка компонентов
при интерполяции.

## Трёхцветный инвариант

В QRS-координатах класс можно представить нормализованным остатком по модулю `3`:

```text
OddR и EvenR: class = mod3(Q - R)
OddQ и EvenQ: class = mod3(R - Q)
```

`mod3` здесь всегда возвращает `0`, `1` или `2`, в том числе для отрицательных координат.
Пользовательскому коду не нужно воспроизводить формулу: методы расширения учитывают раскладку и
корректно работают с индексами строк и столбцов.

<xref:Akeldov.Math.Hexes.Chromatization.VectorXYIntExtensions> предоставляет:

- `GetChromaticClass(layout)` для любой поддерживаемой раскладки;
- `GetOddRChromaticClass()`, `GetEvenRChromaticClass()`, `GetOddQChromaticClass()` и
  `GetEvenQChromaticClass()` для кода, где раскладка заранее известна.

Передача значения `Layout` вне четырёх поддерживаемых вариантов приводит к
`ArgumentOutOfRangeException`.

## Отдельный индекс и карта классов

Для разового запроса вычисляйте класс напрямую. Если классы многократно читаются для конечной
карты, создайте <xref:Akeldov.Math.Hexes.Chromatization.ChromaticIndexMap>:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Chromatization;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(
    width: 4,
    height: 3,
    layout: Layout.OddR);

var index = new VectorXYInt(2, 1);
int computedClass = index.GetChromaticClass(topology.Layout);

var classes = new ChromaticIndexMap(topology);
byte storedClass = classes[index];

// computedClass == storedClass
```

`ChromaticIndexMap` заранее вычисляет одно байтовое значение на ячейку и реализует доступный
только для чтения `ISpatialHexMap<byte>`. Конструктор с
<xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry> сохраняет переданную геометрию. Конструктор с
одной топологией создаёт для неё геометрию с единичным радиусом. В обоих случаях сами классы
зависят только от разрешения и раскладки.

## Геометрический порядок тройки

Около каждой вершины гексагональной сетки сходятся три гекса. Обычная
<xref:Akeldov.Math.Hexes.Topology.Triplet`1> хранит их в геометрическом порядке:

- `Main` — гекс, содержащий точку выборки;
- `Left` и `Right` — два его соседа у ближайшей вершины.

`GetChromaticTriplet(layout)` преобразует `Triplet<VectorXYInt>` в `Triplet<byte>`, но сохраняет
этот порядок. Значения `Main`, `Left`, `Right` становятся номерами классов соответствующих
гексов. Поскольку три гекса попарно смежны, тройка содержит `0`, `1` и `2`, однако их позиции
зависят от выбранной вершины.

Не считайте `Main` синонимом класса `0`, `Left` — класса `1`, а `Right` — класса `2`.

## Хроматический порядок

<xref:Akeldov.Math.Hexes.Topology.ChromaticTriplet`1> использует другой контракт. Свойства
`Index0`, `Index1`, `Index2` относятся к классам `0`, `1`, `2` независимо от геометрического
положения гексов. Такой порядок позволяет одному и тому же каналу всегда представлять один
хроматический класс.

Это различие особенно важно для барицентрических весов:

| Тип растра | Значение | Порядок |
|---|---|---|
| <xref:Akeldov.Math.Hexes.Topology.ChromaticIndexTripletRaster> | `Triplet<byte>` | Классы гексов в порядке `Main`, `Left`, `Right` |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticIndexPartialTripletRaster> | `PartialTriplet<byte>` | Тот же геометрический порядок с флагами присутствия |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticBarycentricTripletRaster> | `ChromaticTriplet<float>` | Веса, переставленные в `Index0`, `Index1`, `Index2` |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticBarycentricPartialTripletRaster> | `PartialChromaticTriplet<float>` | Те же веса с флагами присутствия для каждого класса |

Для каждой ячейки растра алгоритм берёт точку в её центре, находит содержащий её гекс и
ближайшую вершину этого гекса. Затем используются содержащий гекс и два соседа, сходящиеся в этой
вершине. `SourceHexMapGeometry` задаёт исходную сетку, а `Geometry` и `Resolution` — отдельную
сетку точек выборки.

## Полные и частичные растры

Полные растры продолжают логическую гексагональную решётку за границами конечной карты. Класс
любого внешнего индекса всё равно определён, а барицентрические координаты можно вычислить для
полной тройки. Но таким внешним индексом нельзя безопасно обращаться к ограниченной карте
значений.

Частичные растры сопоставляют каждую позицию исходной топологии и сохраняют маску присутствия:

- `PartialTriplet<byte>` использует `HasMain`, `HasLeft`, `HasRight`;
- `PartialChromaticTriplet<float>` использует `HasIndex0`, `HasIndex1`, `HasIndex2`.

Проверяйте эти флаги до чтения соответствующего значения из другой конечной карты. Содержимое
отсутствующей позиции не заменяет проверку маски.

Растр можно создать только из `HexMapGeometry`, чтобы он автоматически покрывал карту, либо
передать отдельную `RasterGeometry` для нужных начала, размера и разрешения выборки. Размеры
исходной карты и разрешение растра должны быть положительными.

## Когда использовать классы

- Обрабатывайте по одному классу за проход, если одновременно изменяемые ячейки не должны иметь
  общего ребра.
- Используйте `Index0`, `Index1`, `Index2` как устойчивые каналы при смешивании трёх значений
  около вершины.
- Применяйте `ChromaticIndexMap` для визуализации или повторных запросов по конечной карте.

Трёхцветный инвариант гарантирует отсутствие соседей только внутри одного класса. Если операция
затрагивает ячейки дальше непосредственного соседа по ребру, одной хроматизации может быть
недостаточно для независимого параллельного прохода.
