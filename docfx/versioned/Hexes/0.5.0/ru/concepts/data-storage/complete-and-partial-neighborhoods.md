# Полные и частичные окрестности

Операции с гексагональной сеткой часто возвращают небольшой фиксированный набор связанных
значений. Akeldov.Math.Hexes использует упорядоченные типы значений вместо коллекций переменного
размера, поэтому каждая позиция сохраняет устойчивый смысл.

Полное значение всегда хранит все логические позиции. Частичное значение хранит те же поля и
добавляет флаги, указывающие, какие позиции семантически присутствуют. Это различие важно у
границы конечной <xref:Akeldov.Math.Hexes.HexMapTopology>.

## Порядок позиций

| Полный тип | Частичный тип | Порядок позиций | Типичное значение |
|---|---|---|---|
| `Pair<T>` | `PartialPair<T>` | `Left`, `Right` | Два соседа у выбранной вершины |
| `Triplet<T>` | `PartialTriplet<T>` | `Main`, `Left`, `Right` | Исходный гекс и два соседа, встречающихся с ним в вершине |
| `Sextuplet<T>` | `PartialSextuplet<T>` | `Adjacent0` … `Adjacent5` | Шесть соседей по ребру без центрального значения |
| `Septuplet<T>` | `PartialSeptuplet<T>` | `Main`, `Adjacent0` … `Adjacent5` | Исходный гекс и шесть соседей по ребру |
| `ChromaticTriplet<T>` | `PartialChromaticTriplet<T>` | `Index0`, `Index1`, `Index2` | Три значения в порядке хроматических классов |

В секстетах и септетах `Adjacent0` … `Adjacent5` точно соответствуют
<xref:Akeldov.Math.Hexes.Topology.HexEdge.Edge0> …
<xref:Akeldov.Math.Hexes.Topology.HexEdge.Edge5>. Физические
направления зависят от раскладки и чётности строки или столбца, но порядок номеров рёбер не
меняется.

Полные контейнеры можно напрямую создавать и деконструировать:

```csharp
using Akeldov.Math.Hexes.Topology;

var values = new Sextuplet<string>(
    "edge 0", "edge 1", "edge 2",
    "edge 3", "edge 4", "edge 5");

var (edge0, edge1, edge2, edge3, edge4, edge5) = values;
```

Эти обобщённые `readonly struct` только переносят данные. Их конструкторы не проверяют границы
карты и не назначают геометрический смысл; смысл полей определяет создающая их операция.

## Частичные значения

Каждый частичный тип предоставляет битовую маску `Presence` и соответствующие свойства `Has...`.
Источником истины служит маска, а не сохранённое значение: отсутствующее поле может случайно
совпасть с допустимым значением.

| Частичный тип | Флаги наличия |
|---|---|
| `PartialPair<T>` | `PairPresenceFlags` |
| `PartialTriplet<T>` | `TripletPresenceFlags` |
| `PartialSextuplet<T>` | `SextupletPresenceFlags` |
| `PartialSeptuplet<T>` | `SeptupletPresenceFlags` |
| `PartialChromaticTriplet<T>` | `ChromaticTripletPresenceFlags` |

Каждое перечисление флагов определяет `None` и `All`. Методы `ToPair`, `ToTriplet`, `ToSextuplet`
и `ToSeptuplet` возвращают все сохранённые значения и намеренно отбрасывают маску. Выполняйте
преобразование только после обработки отсутствующих позиций.

«Полный» не означает «находящийся в этой карте». Все шесть логических соседей существуют в
бесконечной гексагональной сетке, поэтому полная индексная окрестность может содержать координаты
за пределами ограниченной топологии.

## Выборка значений шести соседей

`SampleSextuplet` читает шесть значений вокруг внутренней ячейки, не читая её центр:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Topology;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(3, 3, Layout.OddR);
var map = new IntHexMap(topology, new int[topology.Count]);

Sextuplet<int> neighbors =
    map.SampleSextuplet(new VectorXYInt(1, 1));
```

Центр и все шесть соседей должны находиться внутри карты. Метод проверяет все координаты до
чтения первого значения и выбрасывает `ArgumentOutOfRangeException`, если полная окрестность не
помещается.

На границе используйте `SamplePartialSextuplet`:

```csharp
PartialSextuplet<int> corner =
    map.SamplePartialSextuplet(VectorXYInt.Zero);

if (corner.HasAdjacent0)
{
    int edge0Value = corner.Adjacent0;
}
```

Внутри карты должен находиться только центр. Отсутствующие соседи содержат `default(TValue)`, а их
флаги сброшены. Оба метода работают через `IHexMap<TValue>`, включая пространственные карты,
выбирают смещения по раскладке и чётности и не выделяют массивы.

## Предвычисленные индексные окрестности

Используйте `IndexSeptupletMap` или `IndexPartialSeptupletMap`, если для каждой исходной ячейки
много раз читается одна индексная окрестность. В отличие от выборки соседних значений эти карты
хранят центральный индекс `Main` вместе с шестью соседними индексами.

`IndexSeptupletMap` сохраняет все координаты бесконечной сетки, даже если соседний индекс находится
за границей топологии. `IndexPartialSeptupletMap` хранит те же логические координаты и сбрасывает
флаги соседей за границей. При любом допустимом обращении `Main` присутствует.

```csharp
var neighborhoods = new IndexPartialSeptupletMap(topology);
PartialSeptuplet<VectorXYInt> neighborhood =
    neighborhoods[VectorXYInt.Zero];

int total = map[neighborhood.Main];
if (neighborhood.HasAdjacent0)
    total += map[neighborhood.Adjacent0];
```

## Выборка окрестностей в растры

Растры индексов отвечают на вопрос пространственной выборки, а не поиска по исходной ячейке:

- `IndexTripletRaster` и `IndexPartialTripletRaster` хранят содержащий точку гекс и два гекса,
  встречающихся с ним в ближайшей вершине;
- `IndexSeptupletRaster` и `IndexPartialSeptupletRaster` хранят содержащий гекс и все шесть
  соседей по ребру.

Полные растры используют координаты бесконечной сетки. Частичные растры сохраняют порядок позиций
и используют флаги, когда конечная исходная топология не содержит позицию. Геометрия,
индексирование и поведение у границ описаны на странице [«Растры»](rasters.md).

## Владение данными

Полные и частичные контейнеры — типы значений со свойствами только для чтения. Передача контейнера
копирует его поля. Обобщённые значения могут ссылаться на изменяемые объекты; контейнеры их не
клонируют.

Специализированные карты окрестностей и растры владеют предвычисленным хранилищем и предоставляют
индексаторы только для чтения. Каждое обращение возвращает структуру окрестности по значению,
поэтому вызывающий код не может заменить элементы внутреннего хранилища.
