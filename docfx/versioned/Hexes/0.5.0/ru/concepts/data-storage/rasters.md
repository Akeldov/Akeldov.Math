# Растры

Растры Hexes — это предварительно рассчитанные пространственные таблицы поиска. Для каждой ячейки
прямоугольной сетки выборки они хранят индексы гексов, барицентрические веса, хроматические классы
или комбинацию этих значений. Они реализуют контракт Spatial2D `ISpatialRaster<T>`, но их отсчёты
представляют семантические данные, а не пиксели изображения.

Это важное различие: создание `IndexTripletRaster` не рисует гексагональную карту. Оно подготавливает
данные для многократного поиска или интерполяции значений карты. Получение цветного или полутонового
изображения — отдельный этап [растеризации](../rasterization.md).

## Исходная геометрия и геометрия выборки

Каждый растр объединяет две независимые геометрии:

- <xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry> описывает исходную гексагональную сетку: её
  ограниченную <xref:Akeldov.Math.Hexes.HexMapTopology>, раскладку, центр нулевого гекса и радиус
  гекса;
- тип Spatial2D `RasterGeometry` описывает осевой прямоугольник выборки: его левый нижний `Origin`,
  пространственный `Size`, целочисленный `Resolution` и вычисляемый `CellSize`.

Отсчёт с растровыми координатами `(x, y)` вычисляется в центре соответствующей ячейки растра:

```text
sampleX = Geometry.Origin.X + (x + 0.5) * Geometry.CellSize.X
sampleY = Geometry.Origin.Y + (y + 0.5) * Geometry.CellSize.Y
```

Следовательно, свойство `Resolution` растра равно `Geometry.Resolution`, а не
`Topology.Resolution` гексагональной карты. Одна ячейка растра — это одна пространственная выборка,
а не один гекс.

У каждого типа растра есть два конструктора. Если передать только геометрию гексагональной карты,
будет использован вызов `hexMapGeometry.ToRasterGeometry(1f)`: сетка покрывает ограничивающий
прямоугольник всей карты с минимальной плотностью один отсчёт на апофему гекса и при необходимости
округляет разрешение вверх. Передайте явный `RasterGeometry`, чтобы выбрать другой прямоугольник
или разрешение:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Geometry;
using Akeldov.Math.Hexes.Topology;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Rasterization;

var topology = new HexMapTopology(8, 6, Layout.OddR);
var source = new HexMapGeometry(
    topology,
    origin: new VectorXY(10f, 20f),
    radius: 2f);

RasterGeometry sampling = source.ToRasterGeometry(
    pixelsPerApothem: 4f,
    margin: 1f);

var raster = new IndexPartialTripletRaster(source, sampling);
```

Используйте один и тот же `RasterGeometry`, если несколько растров должны описывать одинаковые
ячейки выборки. Совпадения только разрешений недостаточно: начала координат и размеры также должны
совпадать.

## Выбор хранимого отсчёта

Пакет предоставляет десять типов растров в пространстве имён
`Akeldov.Math.Hexes.Topology`. Все они поддерживают четыре значения
<xref:Akeldov.Math.Hexes.Layout>.

| Растр | Значение отсчёта | Назначение | `TryGetValue` |
| --- | --- | --- | --- |
| <xref:Akeldov.Math.Hexes.Topology.IndexTripletRaster> | `Triplet<VectorXYInt>` | Главный гекс и два гекса, сходящиеся с ним в ближайшей вершине | Да |
| <xref:Akeldov.Math.Hexes.Topology.IndexPartialTripletRaster> | `PartialTriplet<VectorXYInt>` | Та же тройка, обрезанная по исходной топологии | Да |
| <xref:Akeldov.Math.Hexes.Topology.IndexSeptupletRaster> | `Septuplet<VectorXYInt>` | Главный гекс и все шесть соседей по ребру | Нет |
| <xref:Akeldov.Math.Hexes.Topology.IndexPartialSeptupletRaster> | `PartialSeptuplet<VectorXYInt>` | Те же логические индексы с флагами попадания в границы, если `Main` находится внутри топологии | Нет |
| <xref:Akeldov.Math.Hexes.Topology.BarycentricTripletRaster> | `Triplet<float>` | Веса для треугольника центров `Main`–`Left`–`Right` | Да |
| <xref:Akeldov.Math.Hexes.Topology.BarycentricPartialTripletRaster> | `PartialTriplet<float>` | Те же веса с отсутствующими позициями за пределами карты | Да |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticIndexTripletRaster> | `Triplet<byte>` | Хроматические классы гексов `Main`–`Left`–`Right` | Да |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticIndexPartialTripletRaster> | `PartialTriplet<byte>` | Те же классы с отсутствующими позициями за пределами карты | Нет |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticBarycentricTripletRaster> | `ChromaticTriplet<float>` | Веса, переупорядоченные по хроматическим классам 0, 1 и 2 | Да |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticBarycentricPartialTripletRaster> | `PartialChromaticTriplet<float>` | Хроматически упорядоченные веса с флагами наличия | Да |

### Тройки индексов

Для каждой точки выборки растр троек индексов сначала классифицирует главный гекс. Затем он выбирает
ближайшую вершину этого гекса и записывает ещё два гекса, сходящиеся с главным в этой вершине.
Результат упорядочен как `Main`, `Left`, `Right`; порядок учитывает раскладку и одинаков для растров
индексов, барицентрических координат и хроматических индексов.

Используйте `Main`, если нужен только содержащий точку или ближайший гекс. Сохраняйте все три
позиции при интерполяции значений, заданных в центрах гексов:

```csharp
var indexRaster = new IndexTripletRaster(source, sampling);
var sampleIndex = new VectorXYInt(12, 7);

Triplet<VectorXYInt> indices = indexRaster[sampleIndex];
VectorXYInt main = indices.Main;
VectorXYInt left = indices.Left;
VectorXYInt right = indices.Right;
```

Полные тройки описывают бесконечную гексагональную сетку, задаваемую исходной геометрией. Поэтому
около границы конечной карты или за её пределами один или несколько возвращённых индексов могут
быть отрицательными либо не меньше соответствующей компоненты разрешения карты.

### Семёрки индексов

Растр семёрок индексов хранит классифицированный гекс `Main`, а затем шесть его соседей по ребру в
позициях от `Adjacent0` до `Adjacent5`. Соседние позиции следуют принятому в библиотеке порядку
рёбер гекса и потому зависят от раскладки при представлении индексами строки и столбца.

Используйте семёрки для фиксированных ядер из семи ячеек, клеточных правил и фильтров окрестности.
Они не представляют треугольник из трёх центров, применяемый для интерполяции; в пакете нет
барицентрических или хроматических вариантов семёрки.

### Барицентрические тройки

Барицентрический растр хранит координаты точки выборки в треугольнике, образованном центрами тех же
гексов `Main`, `Left` и `Right`, которые выбирает растр троек индексов. Объединяйте растры,
построенные по одинаковым исходной геометрии и геометрии выборки:

```csharp
var indices = new IndexPartialTripletRaster(source, sampling);
var weights = new BarycentricPartialTripletRaster(source, sampling);
var sampleIndex = new VectorXYInt(12, 7);

PartialTriplet<VectorXYInt> cells = indices[sampleIndex];
PartialTriplet<float> barycentric = weights[sampleIndex];

if (cells.HasMain)
{
    VectorXYInt cell = cells.Main;
    float weight = barycentric.Main;
}
```

Три значения полной барицентрической тройки в сумме приблизительно равны `1` с учётом погрешности
чисел с плавающей точкой. Частичный растр сохраняет исходный вес каждой оставшейся позиции и
записывает значение по умолчанию для отсутствующих позиций; оставшиеся веса не нормализуются
повторно.

### Хроматические тройки

Гексагональная сетка имеет повторяющуюся трёхклассовую раскраску. Растр
`ChromaticIndexTripletRaster` хранит класс (`0`, `1` или `2`) тех же ячеек `Main`, `Left` и `Right`.
Эти три ячейки сходятся в одной вершине, поэтому полная тройка содержит все три класса.

`ChromaticBarycentricTripletRaster` объединяет представления классификации и интерполяции. Он
переупорядочивает барицентрические веса в `Index0`, `Index1` и `Index2`, поэтому смысл компонента
остаётся постоянным при изменении порядка `Main`–`Left`–`Right` по сетке. Частичный вариант
переупорядочивает вместе с весами и флаги наличия.

Схема классов и их применение описаны в разделе
[«Хроматизация»](../spatial-algorithms/chromatization.md).

## Полные и частичные растры

Полные растры сохраняют результат для бесконечной сетки. Они подходят, если вызывающий код имеет
данные с запасом по границе, намеренно делает выборку за пределами конечной карты или использует
геометрические сведения независимо от принадлежности карте.

Частичные растры проверяют каждый упомянутый гекс по прямоугольной исходной топологии:

```text
0 <= hexIndex.X < SourceHexMapGeometry.Topology.Resolution.X
0 <= hexIndex.Y < SourceHexMapGeometry.Topology.Resolution.Y
```

Наличие определяется флагами, а не сохранённым содержимым. Частичные растры троек записывают
`default(T)` в отсутствующие позиции. `IndexPartialSeptupletRaster`, напротив, сохраняет каждый
вычисленный логический индекс даже при снятом флаге; если `Main` находится вне исходной топологии,
все семь флагов сняты, даже когда один из сохранённых соседних индексов попадает внутрь.

Доступны следующие флаги:

- `PartialTriplet<T>` предоставляет `HasMain`, `HasLeft`, `HasRight` и свойство `Presence` типа
  `TripletPresenceFlags`;
- `PartialSeptuplet<T>` предоставляет `HasMain`, свойства от `HasAdjacent0` до `HasAdjacent5` и
  свойство `Presence` типа `SeptupletPresenceFlags`;
- `PartialChromaticTriplet<T>` предоставляет `HasIndex0`, `HasIndex1`, `HasIndex2` и
  свойство `Presence` типа `ChromaticTripletPresenceFlags`.

Нельзя определять отсутствие по сохранённому значению. `(0, 0)` — допустимый индекс карты,
хроматический класс `0` допустим, а барицентрический вес может на законных основаниях быть равен
`0`. Проверяйте соответствующее свойство `Has...` или флаг `Presence`. Общая модель наличия
описана в разделе
[«Полные и частичные окрестности»](complete-and-partial-neighborhoods.md).

## Безопасное индексирование ячеек растра

Экземпляры растров предоставляют `SourceHexMapGeometry`, `Geometry` и `Resolution`, а также три
индексатора только для чтения. У `IndexTripletRaster` дополнительно есть свойство `Topology`; для
остальных растров используйте `SourceHexMapGeometry.Topology`.

```csharp
Triplet<VectorXYInt> byCoordinates = indexRaster[12, 7];
Triplet<VectorXYInt> byVector = indexRaster[new VectorXYInt(12, 7)];
Triplet<VectorXYInt> byFlatIndex = indexRaster[7 * indexRaster.Resolution.X + 12];
```

Плоские индексы используют построчный порядок:

```text
flatIndex = y * Resolution.X + x
```

Индексатор `VectorXYInt` проверяет обе координаты и за пределами растра создаёт
`IndexOutOfRangeException`. Плоский индексатор использует обычные границы массива. Перегрузка
`(x, y)` непосредственно вычисляет построчный индекс, поэтому применяйте её только после проверки
обеих координат; для непроверенных индексов предпочтителен векторный индексатор или доступный
метод `TryGetValue`.

Поведение `TryGetValue` неодинаково для разных частичных типов:

- полные растры троек и хроматически-барицентрические растры возвращают `true` для любого индекса
  внутри растра выборки;
- `IndexPartialTripletRaster` и `BarycentricPartialTripletRaster` возвращают `true`, только если
  присутствует хотя бы одна позиция исходной карты;
- `ChromaticBarycentricPartialTripletRaster` проверяет границы растра, но может вернуть `true` при
  `Presence == None`;
- у растров семёрок и `ChromaticIndexPartialTripletRaster` нет `TryGetValue`, поэтому
  сначала проверяйте границы, а после индексирования исследуйте флаги наличия.

Эти правила разделяют два разных вопроса: существует ли ячейка растра и ссылается ли она хотя бы
на один гекс внутри конечной исходной карты.

## Владение и стоимость

Конструктор выделяет внутренний построчный массив из `Resolution.X * Resolution.Y` отсчётов и сразу
полностью его заполняет. Растр владеет этим хранилищем и не предоставляет ни исходную коллекцию, ни
сеттеры. Индексаторы возвращают структуры-значения только для чтения, поэтому вызывающий код не
может изменить предвычисленный растр через полученный отсчёт.

Время создания и занимаемая память пропорциональны числу ячеек выборки. Тип отсчёта определяет
размер одной ячейки: семёрка больше тройки, а частичные значения дополнительно хранят флаги наличия.
Повторно используйте растр для множества запросов с одинаковыми геометриями; для единственной точки
прямые функции преобразования координат и поиска соседей не требуют полного предвычисления.

## Проверка аргументов и поведение на границах

Для создания растра нужны положительные размеры как исходной топологии, так и разрешения выборки.
Пустая `HexMapTopology` допустима сама по себе, но для этих растров непригодна. Размер массива
вычисляется с проверкой и создаёт `OverflowException`, если общее число ячеек выборки не помещается
в длину массива.

`RasterGeometry` при создании проверяет конечность начала координат, конечный положительный размер
и положительное разрешение. `ToRasterGeometry()` дополнительно требует конечный положительный
`pixelsPerApothem`, конечный неотрицательный отступ, корректную непустую геометрию гексов и
результирующее разрешение в диапазоне `Int32`.

Во всех четырёх раскладках используются детерминированные правила классификации точки по гексу и
выбора ближайшей вершины. Отсчёты точно на общей границе следуют правилам разрешения равенства этих
функций; увеличение разрешения не меняет правило, а лишь набор центров ячеек выборки. Подробнее
границы описаны в разделе
[«Дискретизация координат»](../fundamentals/coordinate-discretization.md).
