# Геометрия гексагональной сетки

Геометрия гексагональной сетки размещает логические индексы гексов в непрерывном декартовом
пространстве Akeldov.Math.Spatial2D. <xref:Akeldov.Math.Hexes.HexMapTopology> определяет, какие
ячейки существуют и как они индексируются, а <xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry>
добавляет их физический размер и положение.

Все расстояния и позиции используют одну единицу пространства координат. Это могут быть пиксели,
метры или единицы игрового мира, но в пределах одной операции единица должна оставаться общей.

## Размер и ориентация

Правильный гекс задаётся двумя расстояниями:

- **радиус** `R`: от центра до вершины;
- **апофема** `A`: от центра до середины ребра.

Они связаны формулами:

```text
A = R * sqrt(3) / 2
R = A * 2 / sqrt(3)
```

Преобразования выполняют методы `ConvertHexRadiusToApothem()` и
`ConvertHexApothemToRadius()`. Оба значения должны быть конечными и больше нуля.

<xref:Akeldov.Math.Hexes.Layout> определяет ориентацию и правило нечётного или чётного смещения:

| Раскладки | Ориентация | Первая нормализованная вершина | Углы вершин |
| --- | --- | --- | --- |
| `OddR`, `EvenR` | `PointyTop` | 30 градусов | 30, 90, 150, 210, 270, 330 градусов |
| `OddQ`, `EvenQ` | `FlatTop` | 0 градусов | 0, 60, 120, 180, 240, 300 градусов |

Углы в таблице отсчитываются против часовой стрелки от положительной оси X в координатах
Spatial2D. Нечётный и чётный варианты имеют одинаковую форму гекса и базис QRS; различие
возникает только при кодировании ячеек QRS прямоугольными индексами `VectorXYInt`. Четыре правила
смещения описаны на странице [«Раскладки»](../fundamentals/layouts.md).

## Размещение карты

`HexMapGeometry` — неизменяемое значение, которое объединяет четыре связанных параметра:

- `Topology`: разрешение и раскладку;
- `Origin`: центр нулевого гекса в виде `VectorXY`; его индексы QRS и хранилища равны нулю;
- `Radius`: расстояние от центра до вершины в единицах пространства координат;
- `Apothem`: вычисленное расстояние от центра до ребра в тех же единицах.

Задавайте начало явно, когда сетку нужно совместить с существующей системой координат:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Geometry;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(
    width: 8,
    height: 6,
    layout: Layout.OddR);

var geometry = new HexMapGeometry(
    topology,
    origin: new VectorXY(100f, 50f),
    radius: 10f);
```

Перегрузка без `origin` использует значение, зависящее от ориентации:

| Ориентация | Центр нулевого гекса по умолчанию |
| --- | --- |
| `PointyTop` | `(apothem, radius)` |
| `FlatTop` | `(radius, apothem)` |

Такое значение размещает один нулевой гекс у положительных осей координат. Оно не является
минимальным углом всей карты. В частности, смещённые строки `EvenR` и смещённые столбцы `EvenQ`
могут выходить ниже соответствующей координаты X или Y по умолчанию.

## Вычисление центров гексов

Для индекса хранилища `(x, y)`, начала `(originX, originY)`, радиуса `R` и апофемы `A` центр
вычисляется так:

| Раскладка | Координата X центра | Координата Y центра |
| --- | --- | --- |
| `OddR` | `originX + 2A*x + A*(y & 1)` | `originY + 1.5R*y` |
| `EvenR` | `originX + 2A*x - A*(y & 1)` | `originY + 1.5R*y` |
| `OddQ` | `originX + 1.5R*x` | `originY + 2A*y + A*(x & 1)` |
| `EvenQ` | `originX + 1.5R*x` | `originY + 2A*y - A*(x & 1)` |

Побитовое выражение чётности правильно распознаёт и отрицательные нечётные индексы. Вместо
повторения формул используйте `VectorXYInt.GetHexCenter()`:

```csharp
var index = new VectorXYInt(2, 3);

VectorXY center = index.GetHexCenter(
    geometry.Radius,
    geometry.Origin,
    geometry.Topology.Layout);
```

Перегрузка без начала использует приведённый выше центр по умолчанию. Для индекса QRS вызовите
`VectorQRSInt.GetHexOffset(radius, layout)` и прибавьте нужное начало. Статический метод
`GetHexCenter(q, r, radius, layout)` также принимает Q и R напрямую, но использует начало по
умолчанию.

Во всём преобразовании необходимо использовать одинаковые радиус и раскладку. Базис перехода
из QRS в XY и обратное преобразование описаны на странице
[«Пространственные координаты»](../fundamentals/coordinate-systems/spatial-coordinates.md).

## Получение вершин

`GetHexVertices(radius, layout)` разворачивает известный центр `VectorXY` в шесть вершин:

```csharp
VectorXY[] vertices = center.GetHexVertices(
    geometry.Radius,
    geometry.Topology.Layout);
```

Результат — новый изменяемый массив из шести элементов, принадлежащий вызывающему коду. Вершины
следуют против часовой стрелки в порядке из таблицы ориентаций. Метод
`GetNormalizedHexVertices(layout)` возвращает те же смещения для гекса единичного радиуса, также
в новом массиве вызывающего кода. Чтобы получить мировые позиции, умножьте каждое смещение на
радиус и прибавьте центр.

Есть и перегрузка QRS — `GetHexVertices(q, r, radius, layout)`. Как и соответствующий метод центра,
она использует центр нулевого гекса по умолчанию для выбранной раскладки.

Для поиска ближайшей вершины используйте:

- `PointXY.GetClosestVertexIndex(radius, center, layout)` для известного гекса; метод возвращает
  индекс от 0 до 5 в том же порядке вершин;
- `PointXY.GetClosestHexVertexIndex(radius, origin, layout)`, чтобы сначала определить содержащий
  гекс, а затем получить его индекс `VectorXYInt` вместе со значением `HexVertex`.

На общей границе гексов содержащая ячейка выбирается по тем же правилам разрешения равенства,
что и при дискретизации координат. Если две вершины находятся на строго одинаковом расстоянии,
выбирается вершина с меньшим индексом, поскольку проверка идёт по порядку. Поведение преобразования
точки в ячейку на границах описано на странице
[«Дискретизация координат»](../fundamentals/coordinate-discretization.md).

## Ограничивающий прямоугольник карты

`HexMapGeometry.GetBoundingBox()` возвращает осевой `Rectangle`, содержащий все гексы карты
целиком. `GetBoundingBoxSize()` возвращает только его размер `VectorXY`. Границы включают внешний
радиус или апофему вокруг первого и последнего центров, а не только диапазон самих центров.

Для положительных ширины `W` и высоты `H` размер равен:

| Ориентация | Ширина границы | Высота границы |
| --- | --- | --- |
| `PointyTop` | `2A*W + (H == 1 ? 0 : A)` | `2R + 1.5R*(H - 1)` |
| `FlatTop` | `2R + 1.5R*(W - 1)` | `2A*H + (W == 1 ? 0 : A)` |

Нечётный или чётный вариант не меняет размер, но может изменить минимальный угол, поскольку
смещение направлено в противоположную сторону. Пусть `O = (originX, originY)`:

| Раскладка | Минимум X | Минимум Y |
| --- | --- | --- |
| `OddR` | `originX - A` | `originY - R` |
| `EvenR` | `originX - A*(H == 1 ? 1 : 2)` | `originY - R` |
| `OddQ` | `originX - R` | `originY - A` |
| `EvenQ` | `originX - R` | `originY - A*(W == 1 ? 1 : 2)` |

В рабочем коде используйте API, чтобы размер и минимальный угол оставались согласованными:

```csharp
var bounds = geometry.GetBoundingBox();
VectorXY size = geometry.GetBoundingBoxSize();

// Эквивалентный вариант, если отдельный объект geometry не нужен:
var sameBounds = topology.GetBoundingBox(
    geometry.Origin,
    geometry.Radius);
```

Топология может иметь нулевую ширину или высоту, но у пустой карты нет геометрического
ограничивающего прямоугольника. Поэтому оба метода границ требуют `W > 0` и `H > 0` и выбрасывают
`ArgumentOutOfRangeException` для пустой карты.

## Предварительное вычисление всех центров

<xref:Akeldov.Math.Hexes.Geometry.HexCenterMap> заранее вычисляет один центр `PointXY` для каждой
ячейки карты. Это полезно, когда множество операций многократно обращается к одной геометрии:

```csharp
var centers = new HexCenterMap(geometry);

PointXY cellCenter = centers[new VectorXYInt(2, 3)];
PointXY sameCell = centers[3 * topology.Resolution.X + 2];
```

Карта доступна только для чтения и предоставляет геометрию и топологию, по которым была построена.
Оба индексатора используют порядок по строкам; индексатор `VectorXYInt` проверяет X и Y по
топологии. Конструктор `HexCenterMap` только из топологии использует единичный радиус и начало по
умолчанию, поэтому при важном физическом масштабе или положении передавайте явный
`HexMapGeometry`.

## Инварианты геометрии

Соблюдайте следующие контракты на границах API:

- радиусы и апофемы должны быть конечными и больше нуля;
- компоненты явно заданных начал, центров и классифицируемых точек должны быть конечными;
- раскладка должна быть одной из `OddR`, `EvenR`, `OddQ` или `EvenQ`;
- `Origin` — центр, а не угол ограничивающего прямоугольника;
- `VectorXY` и `PointXY` не хранят единицы, радиус, начало или раскладку, поэтому эти параметры
  должны передаваться вместе с зависящими от них значениями;
- массивы, возвращаемые методами вершин, являются новыми и принадлежат вызывающему коду.

[«Полигексы»](polyhexes.md), где геометрия строится из конечных масок ячеек. Практические
