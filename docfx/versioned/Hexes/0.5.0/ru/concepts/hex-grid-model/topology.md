# Топология

<xref:Akeldov.Math.Hexes.HexMapTopology> описывает конечную область индексов прямоугольной
гексагональной карты. Это значение объединяет число столбцов и строк с
<xref:Akeldov.Math.Hexes.Layout>, которая задаёт смысл этих индексов со смещением. Этих
данных достаточно, чтобы определить, какие ячейки принадлежат карте и как
интерпретируются их связи в гексагональной сетке.

Топология не хранит значения ячеек, начало координат в мировом пространстве или
размер гекса. Благодаря разделению этих задач одну топологию можно использовать в
картах, таблицах смежности, геометрии и растеризации.

## Создание топологии

Топологию можно создать из отдельных размеров или из разрешения `VectorXYInt`:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Spatial2D;

var fromDimensions = new HexMapTopology(
    width: 4,
    height: 3,
    layout: Layout.OddR);

var fromResolution = new HexMapTopology(
    resolution: new VectorXYInt(4, 3),
    layout: Layout.OddR);

bool same = fromDimensions == fromResolution; // true
```

Созданное значение предоставляет разрешение, число ячеек и раскладку:

| Член | Значение |
|---|---|
| `Resolution.X` | Число столбцов, или ширина |
| `Resolution.Y` | Число строк, или высота |
| `Count` | Общее число ячеек, `Resolution.X * Resolution.Y` |
| `Layout` | Соглашение о смещении и ориентация гексов |

Оба компонента разрешения должны быть неотрицательными. Допустимые раскладки —
`OddR`, `EvenR`, `OddQ` и `EvenQ`. Конструктор выбрасывает `ArgumentOutOfRangeException` для
другого значения и `OverflowException`, если число ячеек не помещается в `Int32`.

Нуль — допустимый размер. Топологии `0 x N`, `N x 0` и `0 x 0` пусты и имеют
`Count == 0`. Некоторые операции, которым нужна реальная пространственная область, например
вычисление охватывающего прямоугольника всей карты, отклоняют пустую топологию, хотя само
значение топологии корректно.

## Прямоугольная область

Прямоугольник задаётся индексами строк и столбцов со смещением. Для топологии
шириной `W` и высотой `H` индекс принадлежит карте тогда и только тогда, когда:

```text
0 <= X < W
0 <= Y < H
```

Верхние границы не включаются. В частности, `(W, 0)` и `(0, H)` лежат вне карты.
`HexMapTopology` служит описанием и не предоставляет индексатор или метод проверки вхождения,
поэтому проверяйте границы перед передачей вычисленного индекса карте:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(4, 3, Layout.OddR);
var index = new VectorXYInt(2, 1);

bool contains =
    index.X >= 0 && index.X < topology.Resolution.X &&
    index.Y >= 0 && index.Y < topology.Resolution.Y;
```

Преобразование координат и вспомогательные методы смежности работают с бесконечной
гексагональной сеткой. Поэтому они могут вернуть отрицательный или иной индекс за пределами
карты; топология не обрезает его по границе и не выполняет циклический перенос.

## Раскладка как часть топологии

Прямоугольник `W x H` можно интерпретировать в четырёх раскладках координат со смещением. `OddR` и
`EvenR` используют ориентацию вершиной вверх и смещают строки; `OddQ` и `EvenQ` используют
ориентацию горизонтальной стороной вверх и смещают столбцы. Изменение только раскладки не меняет
число индексов и границы прямоугольника, но меняет преобразование QRS, смежность и размещение в
пространстве.

Например, индекс хранения `(1, 1)` допустим в обеих топологиях ниже, но его QRS-координата и
соседи интерпретируются через разные раскладки:

```csharp
var oddRows = new HexMapTopology(4, 3, Layout.OddR);
var evenRows = new HexMapTopology(4, 3, Layout.EvenR);

bool equal = oddRows == evenRows; // false
```

Рассматривайте раскладку как часть идентичности карты, а не как параметр отображения. Четыре
соглашения о смещении описаны на странице [«Раскладки»](../fundamentals/layouts.md), а точные
преобразования QRS — на странице
[«Индексы строк и столбцов»](../fundamentals/coordinate-systems/row-and-column-indices.md).

## Переход к линейному индексу

Карты на основе топологии используют построчный порядок. Первой изменяется координата `X`,
поэтому координаты `(x, y)` переходят в:

```text
flatIndex = y * width + x
```

Обратное преобразование для ненулевой ширины выглядит так:

```text
x = flatIndex % width
y = flatIndex / width
```

Для допустимой ячейки `flatIndex` лежит в диапазоне от `0` до `Count - 1`. Раскладка не влияет на это
преобразование; она задаёт гексагональный смысл индекса `(x, y)`.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(4, 3, Layout.OddR);
var terrain = new HexMap<string>(topology);
var index = new VectorXYInt(2, 1);

terrain[index] = "forest";

int flatIndex = index.Y * topology.Resolution.X + index.X; // 6
string value = terrain[flatIndex];                         // "forest"
```

`HexMap<T>` проверяет `VectorXYInt` по обоим размерам. Его линейный целочисленный индексатор
проверяется по обычным правилам массива.

## Неизменяемая семантика значения

`HexMapTopology` — неизменяемый тип-значение. Его можно копировать и совместно использовать без
необходимости управлять владением данными, а равенство сравнивает и `Resolution`, и `Layout`. Топологию также можно
деконструировать:

```csharp
var topology = new HexMapTopology(4, 3, Layout.OddQ);

var (width, height, layout) = topology;

// width == 4, height == 3, layout == Layout.OddQ
string text = topology.ToString();
// HexMapTopology(width: 4, height: 3, layout: OddQ)
```

Благодаря этому топологию удобно использовать как значение конфигурации или ключ словаря. Две
топологии с одинаковыми размерами, но разными раскладками намеренно неравны.

## Разделение топологии, геометрии и данных

Выбирайте наименьшую модель, которая содержит нужную для операции информацию:

| Модель | Содержит | Применяется для |
|---|---|---|
| `HexMapTopology` | Разрешение и раскладка | Границы индексов, число ячеек, связи индексов |
| `HexMapGeometry` | Топология, начало координат в мировом пространстве и радиус гекса | Центры, вершины, границы карты, размещение растра |
| `HexMap<T>` | Топология и одно изменяемое значение на ячейку | Рельеф, стоимости, маски и другие данные ячеек |

Одну топологию можно передать нескольким картам, чтобы их индексы описывали одни и те же ячейки.
При объединении карт сравнивайте их полные значения топологии, а не только разрешения.

Если для операции нужны пространственные координаты, используйте
<xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry>; этот слой описан на странице [«Геометрия»](geometry.md).
Хранение значений по топологии показано на странице [«Карты»](../data-storage/maps.md), а заранее
вычисленная смежность на границах карты — на странице
[«Полные и частичные окрестности»](../data-storage/complete-and-partial-neighborhoods.md).
