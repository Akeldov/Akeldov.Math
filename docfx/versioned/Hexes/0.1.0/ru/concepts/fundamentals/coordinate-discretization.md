# Дискретизация координат

Дискретизация сопоставляет непрерывной координате одну ячейку гексагональной сетки. В
Akeldov.Math.Hexes есть две основные точки входа: округление дробных QRS-координат до
целочисленного QRS-индекса и прямое определение индекса со смещением по точке в мировом пространстве.
Эти операции отличаются от точного преобразования между двумя целочисленными представлениями
одной ячейки.

| Исходное и результирующее представления | Операция | Результат |
| --- | --- | --- |
| <xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRS> → <xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRSInt> | `ToQRSIndex(layout)` | Выбирает ближайший гекс. |
| `PointXY` → `VectorXYInt` | `ToXYIndex(radius, origin, layout)` | Выбирает содержащий точку гекс и возвращает его индекс со смещением. |
| `VectorQRSInt` ↔ `VectorXYInt` | `ToXYIndex(layout)` / `ToQRSIndex(layout)` | Меняет целочисленное представление, не выбирая другую ячейку. |
| <xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRS> → <xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRSInt> | Явное приведение | Усекает компоненты; это не округление к ближайшему гексу. |

Назначение этих типов описано на страницах [«QRS-координаты»](coordinate-systems/qrs-coordinates.md),
[«Индексы строк и столбцов»](coordinate-systems/row-and-column-indices.md) и
[«Пространственные координаты»](coordinate-systems/spatial-coordinates.md).

## Округление дробных QRS-координат

Вызывайте `ToQRSIndex(Layout)`, когда дробный
<xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRS> нужно превратить в индекс одного логического
гекса. Метод выполняет следующие действия:

1. Вычисляет `S` как `-Q - R`.
2. По отдельности округляет `Q`, `R` и `S` с помощью `MathF.Round` (середины округляются к
   ближайшему чётному числу).
3. Если сумма трёх округлённых компонентов перестала быть равна нулю, исправляет компонент с
   наибольшей ошибкой округления по двум оставшимся.
4. Возвращает <xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRSInt>, для которого
   `Q + R + S` строго равно нулю.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Vectors.QRS;
using Akeldov.Math.Spatial2D;

var fractional = new VectorQRS(1.2f, -2.3f); // S = 1.1

VectorQRSInt nearest = fractional.ToQRSIndex(Layout.OddR);
// nearest: Q = 1, R = -2, S = 1

VectorXYInt offset = nearest.ToXYIndex(Layout.OddR);
// offset: X = 0, Y = -2
```

Результат остаётся QRS-индексом: смещение нечётных или чётных строк в него не включается.
Преобразуйте целочисленный результат с той же <xref:Akeldov.Math.Hexes.Layout> только тогда, когда
нужен индекс со смещением для прямоугольного хранилища.

### Равные расстояния и ориентация

У большинства координат есть один ближайший гекс, и результат QRS одинаков для всех раскладок.
Точка точно на общем ребре или вершине может быть равноудалена от нескольких ячеек, поэтому API
применяет детерминированное правило. `OddR` и `EvenR` используют порядок коррекции для гексов
вершиной вверх, а `OddQ` и `EvenQ` — порядок для гексов горизонтальной стороной вверх. В
частности, если наибольшая ошибка одинакова у `Q` и `R`, а ошибка `S` меньше, в построчных
раскладках исправляется `R`, а в раскладках по столбцам — `Q`. Если среди компонентов с
наибольшей ошибкой есть `S`, исправляется `S`.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Vectors.QRS;

var boundary = new VectorQRS(0.5f, 0.5f); // S = -1

VectorQRSInt pointyTop = boundary.ToQRSIndex(Layout.OddR);
// Q = 0, R = 1, S = -1

VectorQRSInt flatTop = boundary.ToQRSIndex(Layout.OddQ);
// Q = 1, R = 0, S = -1
```

Нечётный и чётный варианты одной ориентации всегда одинаково округляют QRS. Различие появляется
только при представлении полученного QRS-индекса в виде строки и столбца со смещением. Все четыре
соглашения описаны на странице [«Раскладки»](layouts.md).

## Явное приведение усекает компоненты

Явное приведение к <xref:Akeldov.Math.Hexes.Vectors.QRS.VectorQRSInt> преобразует `Q` и `R` в
целые числа усечением к нулю, а затем вычисляет `S` по этим двум значениям. Оно не округляет все
компоненты и не ищет ближайший гекс.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Vectors.QRS;

var source = new VectorQRS(1.9f, -2.9f);

VectorQRSInt truncated = (VectorQRSInt)source;
// Q = 1, R = -2, S = 1

VectorQRSInt nearest = source.ToQRSIndex(Layout.OddR);
// Q = 2, R = -3, S = 1
```

Используйте приведение только тогда, когда действительно требуется усечение компонентов. Для
выбора ячейки предназначен `ToQRSIndex`. В частности, не используйте приведение как сокращённый
способ обработки отрицательных координат: например, `-0.9f` превращается в ноль, и результат
смещается к началу координат QRS.

## Определение гекса по точке в мировом пространстве

`PointXY.ToXYIndex(hexRadius, hexFieldOrigin, layout)` находит содержащий точку гекс и возвращает
его индекс со смещением `VectorXYInt`. Концептуально метод выполняет следующие шаги:

1. Вычитает `hexFieldOrigin` из координат точки.
2. Проецирует смещённую точку на оси QRS, заданные ориентацией раскладки.
3. Делит результат на `hexRadius`, переводя его в единицы радиуса гекса.
4. Применяет описанное выше округление кубических координат с учётом ориентации.
5. Преобразует целочисленный QRS-результат по выбранному соглашению о смещении нечётных или
   чётных индексов.

Для смещённой точки `(x, y)` дробные компоненты вычисляются так:

| Ориентация раскладки | Проекция в дробные QRS-координаты |
| --- | --- |
| `OddR`, `EvenR` (вершиной вверх) | `q = (x / sqrt(3) - y / 3) / radius`; `r = (2 * y / 3) / radius` |
| `OddQ`, `EvenQ` (горизонтальной стороной вверх) | `q = (2 * x / 3) / radius`; `r = (y / sqrt(3) - x / 3) / radius` |

`hexRadius` — расстояние от центра до вершины гекса в тех же единицах, что координаты точки и
начала. `hexFieldOrigin` — это **центр нулевого гекса** в мировом пространстве, а не угол карты.
Всегда передавайте радиус, начало и раскладку, с которыми сетка была создана или отрисована.

В следующем примере индекс со смещением преобразуется в центр ячейки, а центр — обратно в тот же
индекс:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Geometry;
using Akeldov.Math.Hexes.Vectors.QRS;
using Akeldov.Math.Spatial2D;

var layout = Layout.OddR;
const float radius = 3f;
var origin = new VectorXY(10f, -20f);
var expected = new VectorXYInt(2, 3);

VectorXY center = expected.GetHexCenter(radius, origin, layout);
var point = new PointXY(center.X, center.Y);

VectorXYInt actual = point.ToXYIndex(radius, origin, layout);
// actual == expected

VectorQRSInt qrs = actual.ToQRSIndex(layout);
// Преобразуйте в QRS, только если следующему алгоритму нужны логические координаты гекса.
```

Перегрузка `GetHexCenter(radius, layout)` использует зависящее от раскладки стандартное начало.
Чтобы преобразовать её результат обратно, получите соответствующий центр нулевого гекса вызовом
`VectorXYInt.Zero.GetHexCenter(radius, layout)` и передайте это значение в `ToXYIndex`.
Произвольный `VectorXY.Zero` не эквивалентен стандартному началу.

### Вспомогательные методы для конкретных раскладок

Если раскладка зафиксирована в данной ветви кода, можно вызвать специализированный метод без
аргумента `Layout`:

| Метод | Эквивалентный общий вызов |
| --- | --- |
| `ToOddRXYIndex(radius, origin)` | `ToXYIndex(radius, origin, Layout.OddR)` |
| `ToEvenRXYIndex(radius, origin)` | `ToXYIndex(radius, origin, Layout.EvenR)` |
| `ToOddQXYIndex(radius, origin)` | `ToXYIndex(radius, origin, Layout.OddQ)` |
| `ToEvenQXYIndex(radius, origin)` | `ToXYIndex(radius, origin, Layout.EvenQ)` |

Не выбирайте метод только по внешней ориентации гекса. `OddR` и `EvenR`, как и `OddQ` и `EvenQ`,
могут присвоить одной физической ячейке разные индексы со смещением. Метод должен соответствовать
полной раскладке топологии.

## Проверка аргументов и границы

`ToQRSIndex(Layout)` выбрасывает `ArgumentOutOfRangeException`, если `Q` или `R` не являются
конечными числами, вычисленный `S` не является конечным, округлённый или исправленный компонент
не помещается в `Int32` либо передано неопределённое значение раскладки.

Явное приведение не предоставляет таких гарантий проверки при выборе ближайшей ячейки.
Используйте его только для конечных `Q` и `R`, которые безопасно преобразуются в `Int32` и дают
помещающийся в `Int32` компонент `S`.

Общий метод определения гекса по точке и все четыре специализированных метода требуют:

- конечные координаты `PointXY`;
- конечный `hexRadius`, строго больший нуля;
- конечные компоненты начала `VectorXY`.

Общий метод также отклоняет неопределённое значение раскладки. Во всех этих случаях выбрасывается
`ArgumentOutOfRangeException`.

Учитывайте следующие граничные случаи:

- Сетка концептуально не ограничена. `ToXYIndex` может вернуть отрицательный индекс или индекс за
  пределами конкретной карты; перед обращением к хранилищу проверьте его по разрешению карты.
- Точка точно на ребре или вершине назначается одной ячейке согласно детерминированному правилу.
  Очень малое изменение числа с плавающей точкой рядом с ребром может выбрать соседнюю ячейку.
- Даже конечные аргументы могут дать непрактично большую нормализованную координату, если точка
  находится очень далеко от начала или радиус крайне мал. Результирующий индекс должен оставаться
  в диапазоне `Int32` и в масштабе, для которого хватает точности `float`.
- Смешение радиуса, начала или раскладки от другой сетки незаметно изменяет результат: метод не
  может обнаружить такую смысловую ошибку.

Далее см. [«Повороты и преобразования»](rotations-and-transformations.md): эти операции намеренно
сохраняют координаты дробными.
