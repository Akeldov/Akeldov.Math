# Разбиение пространства

Akeldov.Math.Hexes переносит взвешенную модель Вороного из Spatial2D на конечную карту гексов.
Каждый гекс целиком назначается одному сайту по мировому положению своего центра. Результат удобно
использовать для территорий, зон влияния и распределения ячеек между опорными точками.

## Дискретное разбиение по центрам

Исходные точки предоставляет <xref:Akeldov.Math.Hexes.Geometry.HexCenterMap>. Для каждого индекса
она вычисляет центр гекса из <xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry>: топологии, начала
координат и радиуса.

Алгоритм сравнивает только эти центры. Он не разрезает гексы линией Вороного и не возвращает
векторные полигоны. Если непрерывная граница проходит через ячейку, вся ячейка всё равно получает
сайт, ближайший к её центру по взвешенной метрике.

Из этого следуют два важных свойства:

- одинаковые топологии с разным началом или радиусом могут получить разные назначения;
- сайт может находиться за пределами геометрии карты и всё равно получить ближайшие гексы.

## Взвешенные сайты

`Site` из пространства имён `Akeldov.Math.Spatial2D.Partitioning.Voronoi` содержит мировую
позицию `Position` и неотрицательный вес `Weight`. Для обычного конечного положительного веса
алгоритм сравнивает:

```text
weightedDistance² = distance(center, site.Position)² / site.Weight²
```

Больший вес уменьшает взвешенное расстояние и расширяет область влияния сайта. Вес не является
добавочной ценой: он масштабирует расстояние до позиции.

Нулевой и бесконечный веса имеют специальные значения:

| Вес | Поведение |
|---|---|
| Конечный и положительный | Участвует в обычном сравнении взвешенных расстояний |
| `0` | Получает только центр, совпадающий с позицией сайта в пределах геометрической точности |
| `float.PositiveInfinity` | Для несовпадающих точек имеет приоритет над конечными весами; среди бесконечных сайтов выбирается ближайший |

Список сайтов не может быть пустым, и хотя бы один сайт должен иметь ненулевой вес. Позиции
должны быть конечными, а веса — неотрицательными и не `NaN`. Вычисленные координаты центров
гексов также должны оставаться конечными.

## Создание разбиения

Следующий пример делит карту из трёх гексов между двумя сайтами одинакового веса:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Geometry;
using Akeldov.Math.Hexes.Partitioning.Voronoi;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Partitioning.Voronoi;

var geometry = new HexMapGeometry(
    width: 3,
    height: 1,
    origin: VectorXY.Zero,
    radius: 1f,
    layout: Layout.OddR);

var centers = new HexCenterMap(geometry);
var sites = new[]
{
    new Site(new PointXY(0f, 0f), weight: 1f),
    new Site(new PointXY(4f, 0f), weight: 1f)
};

VoronoiHexPartitionMap partition =
    centers.ToVoronoiHexPartitionMap(sites);

VoronoiCell assignedCell = partition[new VectorXYInt(1, 0)];
int sourceSiteIndex = assignedCell.SiteIndex;
```

`ToVoronoiHexPartitionMap` — краткая форма создания
<xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiHexPartitioner> и вызова `Partition`. Создайте
экземпляр `VoronoiHexPartitioner` напрямую, если один набор сайтов нужно повторно применять к
нескольким картам центров. Конструктор копирует и проверяет список сайтов.

## Карта результата

<xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiHexPartitionMap> — согласованный результат
только для чтения, реализующий `ISpatialHexMap<VoronoiCell>`.

| Член | Содержимое |
|---|---|
| `Centers` | Исходная карта центров, использованная при разбиении |
| `Topology` и `Geometry` | Топология и геометрия исходной карты центров |
| `partition[index]` | Ячейка Вороного, которой назначен указанный гекс |
| `Cells` | По одной ячейке Вороного для каждого исходного сайта в том же порядке |

Все гексы, назначенные одному сайту, ссылаются на один объект
<xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiCell>. Его данные имеют следующие значения:

- `SiteIndex` — индекс сайта в исходном списке;
- `Site` — скопированное значение сайта;
- `Center` — то же положение, что и `Site.Position`;
- `HexIndexes` — доступный только для чтения список назначенных индексов.

`Cells.Count` всегда равен числу сайтов. Если сайт не получил ни одного центра, соответствующая
ячейка сохраняется с пустым `HexIndexes`. Это позволяет сопоставлять ячейки исходным сайтам без
повторного поиска.

## Изменяемая копия

Назначения в `VoronoiHexPartitionMap` и группировка в `Cells` не могут расходиться, потому что
результат не предоставляет сеттеры. Если после разбиения нужна прикладная переклассификация,
вызовите `ToMutableHexMap()`. Метод возвращает новую принадлежащую вызывающему
`HexMap<VoronoiCell>` с копией назначений.

Изменение этой карты-копии не меняет исходный результат и списки `HexIndexes`. Если приложению
нужно перестроить сами группы, сформируйте новую модель из изменённых назначений, а не считайте
старый `Cells` актуальным для копии.

Вернитесь к [обзору пространственных алгоритмов](index.md) или переходите к
[хроматизации](chromatization.md), если требуется классификация, зависящая только от логического
индекса и раскладки.
