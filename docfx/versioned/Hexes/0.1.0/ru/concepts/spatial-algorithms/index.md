# Пространственные алгоритмы

Akeldov.Math.Hexes предоставляет алгоритмы, которые используют структуру гексагональной сетки
для поиска маршрутов, разбиения карты и устойчивой классификации ячеек. Они работают с одной
моделью индексов и раскладок, но решают разные задачи и требуют разных входных данных.

| Задача | Что определяет результат | Основной результат |
|---|---|---|
| Найти маршрут с наименьшей стоимостью | Топология и стоимости входа и выхода | <xref:Akeldov.Math.Hexes.Pathfinding.HexPath> |
| Назначить гексы ближайшим взвешенным сайтам | Пространственные центры гексов и сайты Вороного | <xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiHexPartitionMap> |
| Разделить соседние гексы на устойчивые классы | Индекс гекса и раскладка | Класс `0`, `1` или `2` |

Поиск пути следует по логическому соседству внутри <xref:Akeldov.Math.Hexes.HexMapTopology>, а
хроматизации достаточно индекса и раскладки. Разбиение Вороного сравнивает положения центров в
непрерывном пространстве, поэтому ему нужна геометрия карты.

## Поиск пути

При поиске пути карта рассматривается как ориентированный взвешенный граф. Каждый гекс образует
вершину, а переходы разрешены между шестью соседями, имеющими общее ребро. Раскладка топологии
определяет, какие индексы считаются соседними у каждой строки или столбца.

<xref:Akeldov.Math.Hexes.Pathfinding.HexTransferCostMap> объединяет две карты с одинаковой
топологией. Стоимость одного шага из `from` в `to` равна сумме стоимости выхода из `from` и
стоимости входа в `to`. Поэтому стоимость обратного перехода может отличаться, даже если обе
ячейки остаются соседними.

`FindShortestPath` применяет алгоритм Дейкстры и возвращает путь с наименьшей суммарной
стоимостью. Все конечные стоимости должны быть неотрицательными, а
`float.PositiveInfinity` обозначает непроходимый вход или выход. Результат
<xref:Akeldov.Math.Hexes.Pathfinding.HexPath> содержит индексы от начального гекса до конечного и
сумму стоимостей всех шагов. Если конечный гекс недостижим, метод возвращает `null`.

Подробнее модель стоимости, ограничения и результат поиска описаны на странице
[«Поиск пути»](pathfinding.md).

## Разбиение пространства

Разбиение Вороного назначает центр каждого гекса одному взвешенному сайту из Spatial2D. В отличие
от поиска пути, оно не следует по рёбрам сетки: алгоритм сравнивает положения из
<xref:Akeldov.Math.Hexes.Geometry.HexCenterMap> с положениями и весами сайтов в непрерывном
пространстве. Увеличение веса позволяет сайту притягивать более удалённые центры.

<xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiHexPartitioner> выполняет назначение, а
<xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiHexPartitionMap> сохраняет согласованный
результат только для чтения. Его индексатор возвращает ячейку Вороного для конкретного гекса, а
`Cells` содержит по одной <xref:Akeldov.Math.Hexes.Partitioning.Voronoi.VoronoiCell> для каждого
исходного сайта, включая сайты без назначенных гексов.

Результат сохраняет топологию и геометрию исходной карты центров. Если назначения нужно изменять
независимо, `ToMutableHexMap()` создаёт новую изменяемую карту и не нарушает согласованность
исходного результата.

Подробнее влияние весов, устройство ячеек и формы результата описаны на странице
[«Разбиение пространства»](space-partitioning.md).

## Хроматизация

Хроматизация задаёт правильную трёхцветную раскраску бесконечной гексагональной решётки. Каждый
индекс получает класс `0`, `1` или `2`, причём любые два гекса с общим ребром относятся к разным
классам. Класс вычисляется детерминированно по индексу и раскладке; значения карты, радиус и
начало координат на него не влияют.

`GetChromaticClass(layout)` подходит для единичного индекса, а
<xref:Akeldov.Math.Hexes.Chromatization.ChromaticIndexMap> заранее сохраняет классы всей карты и
удерживает её геометрию для последующей пространственной выборки. Для каждой точки выборки
хроматические растры находят ближайшую вершину сетки и хранят для трёх сходящихся в ней гексов
либо номера их классов, либо барицентрические веса, упорядоченные по классам. Частичные варианты
дополнительно отмечают отсутствующие гексы у границы конечной карты.

Такая классификация полезна для независимых проходов по несмежным ячейкам и для устойчивого
порядка значений при интерполяции и растеризации. Подробности приведены на странице
[«Хроматизация»](chromatization.md).

## Выбор алгоритма

- Используйте поиск пути, если результат должен учитывать связность карты, препятствия и
  накопленную стоимость последовательных переходов.
- Используйте разбиение Вороного, если каждую ячейку нужно отнести к пространственному сайту с
  учётом его положения и веса.
- Используйте хроматизацию, если нужен повторяемый класс ячейки, отличающийся от классов всех её
  соседей по ребру.

Эти алгоритмы читают топологию, геометрию или карты, описанные в разделе
[«Хранение данных»](../data-storage/index.md). Для регулярной пространственной выборки карт и
картоподобных результатов переходите к разделу [«Растеризация»](../rasterization.md).
