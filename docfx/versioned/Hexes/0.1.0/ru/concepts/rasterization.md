# Растеризация

Растеризация преобразует данные гексагональной карты в прямоугольную сетку выборок Spatial2D.
Каждая ячейка результата хранит значение, полученное в одной точке пространства. Это значение
может быть цветом для изображения, числом для дальнейшего расчёта или любой другой структурой.

Akeldov.Math.Hexes предоставляет три связанные, но разные группы операций:

| Задача | Исходные данные | Результат |
|---|---|---|
| Перенести значения логической карты в заданное разрешение | `IHexMap<TValue>` | `Raster<TColor>` без мирового размещения |
| Выбрать значения пространственной карты в мировой сетке | `ISpatialHexMap<TValue>` | `SpatialRaster<TColor>` с `RasterGeometry` |
| Нарисовать рёбра и подписи сетки | `HexMapGeometry` или `HexMapTopology` | `SpatialRaster<Gray8BitColor>` |

Индексные, барицентрические и хроматические растры отвечают на другой вопрос: они заранее
сохраняют отношения между точкой выборки и соседними гексами. Различие описано ниже в разделе
[«Растры поиска и готовые значения»](#растры-поиска-и-готовые-значения).

## Модель выборки

При растеризации карты каждая ячейка выходного растра проходит одну последовательность:

```text
ячейка растра → её центральная точка → индекс содержащего гекса
              → значение карты → colorSelector → значение результата
```

Алгоритм выбирает гекс по центральной точке ячейки растра. Он не вычисляет площадь пересечения
пикселя с несколькими гексами, не усредняет соседние значения и не интерполирует их. Поэтому
граница между значениями проходит по тем ячейкам растра, центры которых попали по разные стороны
ребра гекса. Повышение разрешения делает эту дискретизацию визуально точнее.

Если центральная точка соответствует индексу за пределами конечной топологии, в результате
остаётся `default(TColor)`, а `colorSelector` для неё не вызывается. Это особенно заметно у
пространственного растра с внешним полем `margin`.

`colorSelector` — обобщённая функция `Func<TValue, TColor>`. Название отражает типичный сценарий,
но `TColor` не обязан быть цветом. Например, карту `float` можно растеризовать в `byte`, другую
числовую структуру или настоящий тип цвета Spatial2D.

## Геометрия выходного растра

`RasterGeometry` описывает прямоугольную сетку в мировом пространстве:

- `Origin` и `Size` задают занимаемый прямоугольник;
- `Resolution` задаёт число столбцов и строк;
- `CellSize` вычисляется из размера и разрешения;
- точка выборки находится в центре каждой ячейки.

<xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry> может создать такую сетку методом
`ToRasterGeometry(pixelsPerApothem, margin)`. Сетка охватывает ограничивающий прямоугольник всех
гексов, после чего необязательное поле добавляется с каждой стороны.

`pixelsPerApothem` — плотность в пикселях на одну апофему гекса. Внутренне она переводится в
плотность на единицу мировых координат, одинаковую по обеим осям. Разрешение каждой оси
округляется вверх, поэтому фактический `CellSize` может быть немного меньше величины, следующей
непосредственно из заданной плотности. `margin` измеряется в тех же мировых единицах, что радиус,
начало и размер геометрии.

Одинаковую операцию можно вызвать на пространственной карте через `map.ToRasterGeometry(...)`
или на топологии, явно передав радиус и начало координат. Используйте готовую геометрию один раз,
если несколько растров должны иметь полностью совпадающие ячейки выборки.

## Логическая карта без геометрии

<xref:Akeldov.Math.Hexes.IHexMap`1> хранит топологию, но не радиус и не начало координат. Перегрузка

```csharp
Raster<TColor> Rasterize(
    VectorXYInt resolution,
    Func<TValue, TColor> colorSelector)
```

временно размещает топологию с единичным радиусом и стандартным началом координат, охватывает её
ограничивающим прямоугольником и выбирает значения в указанное `resolution`. Результат
`Raster<TColor>` содержит разрешение и новый изменяемый массив `Values`, принадлежащий
вызывающему, но не сохраняет мировую геометрию.

Этот вариант подходит для логического предпросмотра, где важны форма раскладки и итоговое число
пикселей. Если карта реализует <xref:Akeldov.Math.Hexes.ISpatialHexMap`1> и её реальное размещение
имеет значение, используйте пространственные перегрузки.

## Пространственная карта

Для `ISpatialHexMap<TValue>` доступны два способа задать сетку результата:

- передать `pixelsPerApothem` и необязательный `margin`, чтобы автоматически покрыть всю карту;
- передать готовую `RasterGeometry`, чтобы выбрать произвольную область и разрешение.

Оба варианта возвращают `SpatialRaster<TColor>` и сохраняют выбранную геометрию результата.
Пользовательская сетка может покрывать только часть карты, выходить за её границы или иметь
начало, не совпадающее с ограничивающим прямоугольником карты.

Следующий пример превращает карту типов местности в RGBA16-изображение. Внешнее поле остаётся
прозрачным, потому что `default(RGBA16BitColor)` имеет нулевые каналы.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Geometry;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Imaging;
using Akeldov.Math.Spatial2D.Rasterization;

var geometry = new HexMapGeometry(
    width: 4,
    height: 3,
    origin: new VectorXY(10f, 20f),
    radius: 2f,
    layout: Layout.OddR);

var terrain = new SpatialHexMap<int>(geometry, new[]
{
    0, 0, 1, 1,
    0, 1, 1, 2,
    1, 1, 2, 2
});

SpatialRaster<RGBA16BitColor> image = terrain.Rasterize(
    pixelsPerApothem: 24f,
    margin: geometry.Radius,
    colorSelector: TerrainColor);

image.SaveAsPng("terrain.png");

static RGBA16BitColor TerrainColor(int terrainType)
{
    return terrainType switch
    {
        0 => new RGBA16BitColor(0x2800, 0x6800, 0xd800, ushort.MaxValue),
        1 => new RGBA16BitColor(0x3200, 0xa000, 0x4800, ushort.MaxValue),
        2 => new RGBA16BitColor(0x8800, 0x8800, 0x8800, ushort.MaxValue),
        _ => new RGBA16BitColor(0xe000, 0x3000, 0x3000, ushort.MaxValue)
    };
}
```

`Rasterize` создаёт растровые данные, но формат файла определяется API Spatial2D. `SaveAsPng`
доступен для поддерживаемых цветовых растров; обобщённый `Raster<T>` сам по себе не означает
изображение.

## Рёбра карты

Растеризация геометрии рисует уникальные отрезки рёбер всех гексов. Общее ребро двух соседних
ячеек обрабатывается один раз. Перегрузка `HexMapGeometry.Rasterize(...)` принимает ширину линии,
дистанцию затухания, цвет ребра, цвет фона и целочисленную плотность `pixelsPerApothem`.

```csharp
SpatialRaster<Gray8BitColor> edges = geometry.Rasterize(
    curveWidth: 0.08f,
    fadeDistance: 0.05f,
    curveColor: Gray8BitColor.Black,
    backgroundColor: Gray8BitColor.White,
    pixelsPerApothem: 24);

edges.SaveAsPng("hex-edges.png");
```

Ширина линии и дистанция затухания измеряются в мировых координатах, а не в пикселях. Поэтому
одни параметры дают одинаковую физическую толщину при разных разрешениях, но разное число
пикселей на переход.

## Топология и подписи координат

Топологию можно нарисовать без предварительного создания `HexMapGeometry`. Метод `Rasterize`
принимает радиус, необязательное начало нулевого гекса и
<xref:Akeldov.Math.Hexes.HexMapTopologyRasterizationOptions>:

| Параметр | Назначение | Единица |
|---|---|---|
| `Margin` | Внешнее поле с каждой стороны | Мировые координаты |
| `CurveWidth` | Ширина ребра | Мировые координаты |
| `FadeDistance` | Дистанция перехода к фону | Мировые координаты |
| `CurveColor` | Значение на центре ребра | `Gray8BitColor` |
| `BackgroundColor` | Значение вне зоны затухания | `Gray8BitColor` |
| `PixelsPerApothem` | Плотность результата | Пиксели на апофему |

Без перегрузки с `origin` центр нулевого гекса располагается в `VectorXY.Zero`.

К растру топологии можно добавить координатные подписи:

- <xref:Akeldov.Math.Hexes.HexMapTopologyXYLabelsRasterizationOptions> выводит `(X, Y)`;
- <xref:Akeldov.Math.Hexes.HexMapTopologyQRSLabelsRasterizationOptions> преобразует индекс с
  учётом раскладки и выводит `(Q, R, S)`;
- перегрузка с обоими объектами накладывает оба слоя.

Каждый объект подписей получает `TrueTypeFont`, размер, цвет, дистанцию сглаживания края и
необязательное смещение от центра гекса. Размер, сглаживание и смещение задаются в мировых
единицах. Шрифт загружает и передаёт вызывающий код.

## Растры поиска и готовые значения

Типы `IndexTripletRaster`, `IndexSeptupletRaster`, `BarycentricTripletRaster` и их частичные или
хроматические варианты уже являются `ISpatialRaster<TValue>`. Они хранят не цвет ячейки карты, а
индексы соседей, веса или классы, вычисленные для каждой точки выборки.

`MapValues(selector)` преобразует каждое уже сохранённое значение в новый тип и сохраняет ту же
`RasterGeometry`. Эта операция не выполняет новую пространственную выборку. Например,
барицентрический растр можно преобразовать в цвет, не повторяя поиск ближайшей вершины.

Используйте:

- `map.Rasterize(...)`, когда каждой точке нужен один содержащий её гекс и значение его карты;
- специализированный растр, когда нужны несколько соседей, веса интерполяции или флаги
  присутствия;
- `MapValues(...)`, когда пространственные отношения уже вычислены и требуется только изменить
  представление значения.

Семейства растров описаны в статье [«Растры»](data-storage/rasters.md), а поведение полных и
частичных окрестностей — в статье
[«Полные и частичные окрестности»](data-storage/complete-and-partial-neighborhoods.md).

## Проверка параметров

- Разрешение выходного растра и размеры исходной карты должны быть положительными.
- `pixelsPerApothem` должен быть конечным и положительным.
- `margin` должен быть конечным и неотрицательным.
- Начало и размер геометрии должны оставаться конечными, а радиус и апофема — положительными.
- `colorSelector` не может быть `null`.
- Если произведение компонентов разрешения или вычисленное разрешение не помещается в `Int32`,
  выбрасывается `OverflowException`.

Все операции, возвращающие растр, создают новый массив результата. Его изменение не меняет
исходную карту или специализированный растр.

Вернитесь к [хранению данных](data-storage/index.md), чтобы выбрать карту или растр-источник, либо
к [пространственным алгоритмам](spatial-algorithms/index.md), чтобы узнать, какие результаты можно
визуализировать этим способом.
