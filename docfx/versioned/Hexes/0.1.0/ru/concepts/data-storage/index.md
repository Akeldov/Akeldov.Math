# Хранение данных

Akeldov.Math.Hexes предоставляет типы для хранения значений, связанных с гексами, и отношений,
вычисленных в узлах регулярного растра Spatial2D. Они опираются на топологию и геометрию из
раздела [«Модель гексагональной сетки»](../hex-grid-model/index.md), но предназначены для разных
направлений поиска.

| Представление | Направление поиска | Типичное применение |
|---|---|---|
| Карта гексов | От индекса гекса к одному значению | Ландшафт, стоимости, флаги, метки или состояние приложения |
| Карта окрестностей | От индекса гекса к центру и шести соседним индексам | Повторные запросы окрестностей конечной сетки |
| Растр выборки | От узла растра к индексам гексов, весам интерполяции или хроматическим классам | Повторная пространственная выборка и интерполяция |

Эти типы не заменяют друг друга. Карта хранит значения ячеек или предоставляет к ним доступ, а
растр заранее вычисляет связь регулярно расположенных точек выборки с исходной гексагональной
сеткой.

## Карты

`IHexMap<TValue>` — интерфейс только для чтения, предоставляющий одно значение на каждую ячейку
<xref:Akeldov.Math.Hexes.HexMapTopology>. `HexMap<TValue>` добавляет изменяемые индексаторы и
хранит значения построчно. Индексатор с `VectorXYInt` явно задаёт координаты X/Y, а плоский
индексатор удобен, когда алгоритм уже обходит элементы в порядке внутреннего хранилища.

`SpatialHexMap<TValue>` связывает ту же модель хранения с
<xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry>. Используйте его, если потребителю нужны и
значения, и физическое размещение ячеек. В Hexes 0.1.0 булевы, целочисленные и вещественные данные
хранятся в `HexMap<bool>`, `HexMap<int>` и `HexMap<float>`.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(
    width: 4,
    height: 3,
    layout: Layout.OddR);

var terrain = new HexMap<string?>(topology);
terrain[new VectorXYInt(1, 1)] = "forest";
```

Создание, владение массивом, индексирование, типизированные и пространственные карты описаны на
странице [«Карты»](maps.md).

## Растры

Растр хранения имеет собственную прямоугольную `RasterGeometry`. Каждая его ячейка представляет
точку выборки и хранит заранее вычисленную связь с геометрией исходной карты гексов. Поэтому
разрешение растра — это количество точек выборки, а не количество гексов.

Семейства растров отвечают на связанные, но разные вопросы:

- растры индексов хранят содержащий точку гекс и выбранных соседей;
- барицентрические растры хранят веса интерполяции для соответствующей тройки;
- хроматические растры хранят индексы классов или веса в устойчивом порядке трёх классов;
- растры троек описывают три гекса вокруг ближайшей вершины сетки, а растры семёрок — содержащий
  гекс и все шесть соседей, смежных с ним по ребру.

Это растры поиска, а не готовые изображения. Они полезны при многократных запросах к одной сетке
выборки; API, создающие изображения, отдельно описаны в разделе
[«Растеризация»](../rasterization.md).

Геометрия растра, семейства значений, индексирование, проверка аргументов и совместное
использование индексов с весами описаны на странице [«Растры»](rasters.md).

## Полные и частичные окрестности

Значения фиксированного размера `Pair<T>`, `Triplet<T>` и `Septuplet<T>` всегда содержат все
логические позиции. Поэтому у границы конечной карты полная окрестность может содержать корректные
индексы бесконечной сетки, которые находятся за пределами карты.

`PartialPair<T>`, `PartialTriplet<T>` и `PartialSeptuplet<T>` добавляют флаги наличия. Частичные
карты и растры сохраняют назначение и порядок позиций, но отмечают элементы, отсутствующие в
конечной исходной области. Такой вариант безопаснее перед обращением к другой ограниченной карте.

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Topology;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(4, 3, Layout.OddR);

var neighborhoods = new IndexPartialSeptupletMap(topology);
var corner = neighborhoods[new VectorXYInt(0, 0)];

if (corner.HasAdjacent0)
{
    VectorXYInt neighbor = corner.Adjacent0;
}
```

Порядок позиций, маски наличия, поведение у границы и безопасный доступ описаны на странице
[«Полные и частичные окрестности»](complete-and-partial-neighborhoods.md).

## Выбор модели хранения

- Используйте карту гексов, если первичный ключ — индекс ячейки, а каждая ячейка имеет одно
  значение.
- Используйте карту окрестностей, если для каждого гекса многократно читаются те же шесть соседей.
- Используйте растр выборки, если первичный ключ — точка регулярного растра Spatial2D.
- Выбирайте полную форму, если соседи бесконечной сетки имеют смысл, а потребитель сам проверяет
  границы.
- Выбирайте частичную форму, если значения будут напрямую использоваться с конечной картой.

Хранилище предоставляет данные и заранее вычисленные отношения, а алгоритмы определяют, как их
использовать. Переходите к [пространственным алгоритмам](../spatial-algorithms/index.md), чтобы
познакомиться с поиском путей, разбиением и хроматизацией на основе этих представлений.
