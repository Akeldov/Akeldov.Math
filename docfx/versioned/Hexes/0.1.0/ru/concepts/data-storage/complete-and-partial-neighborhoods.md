# Полные и частичные окрестности

Операции над гексагональной сеткой часто возвращают небольшой фиксированный набор связанных
значений: двух соседей около вершины, три гекса с общей вершиной или гекс вместе с шестью
соседями по рёбрам. Akeldov.Math.Hexes представляет такие наборы упорядоченными типами-значениями,
а не коллекциями переменного размера.

**Полное** значение означает, что в результате участвуют все логические позиции. **Частичное**
значение хранит те же позиции и добавляет битовую маску, которая показывает, какие из них
смыслово присутствуют. Различие важно на границе конечной
<xref:Akeldov.Math.Hexes.HexMapTopology>: у бесконечной гексагональной сетки соседи остаются, но
ограниченная карта может их не содержать.

## Порядок позиций

У каждого типа есть фиксированный порядок с определённым смыслом. Имена позиций входят в
контракт; эти типы не предоставляют окрестность переменного размера для перебора.

| Полный тип | Частичный тип | Порядок позиций | Обычный смысл |
|---|---|---|---|
| <xref:Akeldov.Math.Hexes.Topology.Pair`1> | <xref:Akeldov.Math.Hexes.Topology.PartialPair`1> | `Left`, `Right` | Два соседа около выбранной вершины гекса |
| <xref:Akeldov.Math.Hexes.Topology.Triplet`1> | <xref:Akeldov.Math.Hexes.Topology.PartialTriplet`1> | `Main`, `Left`, `Right` | Исходный гекс и два соседа с общей вершиной |
| <xref:Akeldov.Math.Hexes.Topology.Septuplet`1> | <xref:Akeldov.Math.Hexes.Topology.PartialSeptuplet`1> | `Main`, `Adjacent0` … `Adjacent5` | Исходный гекс и шесть соседей по рёбрам |
| <xref:Akeldov.Math.Hexes.Topology.ChromaticTriplet`1> | <xref:Akeldov.Math.Hexes.Topology.PartialChromaticTriplet`1> | `Index0`, `Index1`, `Index2` | Три значения, упорядоченные по хроматическому классу |

В семёрке `Adjacent0`–`Adjacent5` соответствуют `HexEdge.Edge0`–`HexEdge.Edge5`. Физическое
направление этих рёбер зависит от раскладки, но порядок номеров рёбер не меняется. В обычной
тройке `Left` и `Right` определяются относительно выбранной вершины и раскладки; это не первые
два элемента семёрки.

Полные типы можно непосредственно создавать и деконструировать:

```csharp
using Akeldov.Math.Hexes.Topology;

var values = new Triplet<string>(
    main: "center",
    left: "left neighbor",
    right: "right neighbor");

var (main, left, right) = values;
```

`Pair<T>`, `Triplet<T>`, `Septuplet<T>` и `ChromaticTriplet<T>` — универсальные контейнеры. Их
конструкторы не определяют, является ли значение допустимым индексом карты, весом интерполяции
или прикладными данными. Смысл позиций задаёт операция, которая создала значение.

## Выбор полной или частичной формы

Используйте полное значение, когда все логические позиции имеют смысл, а потребитель умеет
работать с неограниченной сеткой. Используйте частичное значение, когда результат будет применён
к конечному источнику и каждую позицию нужно проверить перед использованием.

| Вопрос | Полная форма | Частичная форма |
|---|---|---|
| Все ли позиции смыслово присутствуют? | Да | Только позиции с установленным флагом |
| Может ли индекс лежать вне конечной карты? | Да | Он может храниться, но его флаг будет снят |
| Означает ли `default(T)` отсутствие? | Нет | Нет, наличие не зависит от содержимого |
| Очищается ли отсутствующая позиция автоматически? | Неприменимо | Нет, проверяйте флаг наличия |

«Полная» не означает «находящаяся внутри этой карты». Например, у углового гекса существуют все
шесть логических соседей на бесконечной сетке, поэтому полная семёрка содержит все шесть
индексов, даже если пять или шесть из них находятся за пределами небольшой прямоугольной
топологии.

Частичный тип, в свою очередь, не кодирует отсутствие через `null`, `default(T)` или специальное
значение. Присутствующая позиция может законно содержать `default(T)`, а отсутствующая — сохранять
логическое значение, отличное от `default(T)`. Перед использованием частичной позиции всегда
проверяйте свойство `Has...` или `Presence`.

## Чтение и объединение флагов наличия

У каждого частичного семейства есть собственное перечисление `[Flags]` и вспомогательные
свойства:

| Частичный тип | Перечисление | Отдельные флаги и свойства |
|---|---|---|
| `PartialPair<T>` | <xref:Akeldov.Math.Hexes.Topology.PairPresenceFlags> | `Left`, `Right`; `HasLeft`, `HasRight` |
| `PartialTriplet<T>` | <xref:Akeldov.Math.Hexes.Topology.TripletPresenceFlags> | `Main`, `Left`, `Right`; `HasMain`, `HasLeft`, `HasRight` |
| `PartialSeptuplet<T>` | <xref:Akeldov.Math.Hexes.Topology.SeptupletPresenceFlags> | `Main`, `Adjacent0` … `Adjacent5`; соответствующие свойства `Has...` |
| `PartialChromaticTriplet<T>` | <xref:Akeldov.Math.Hexes.Topology.ChromaticTripletPresenceFlags> | `Index0`, `Index1`, `Index2`; соответствующие свойства `Has...` |

Во всех перечислениях определены `None` и `All`. Объединяйте отдельные позиции побитовой
операцией ИЛИ либо используйте перегрузку конструктора с логическим значением для каждой позиции:

```csharp
using Akeldov.Math.Hexes.Topology;

var byFlags = new PartialTriplet<int>(
    main: 10,
    left: 20,
    right: 30,
    presence: TripletPresenceFlags.Main | TripletPresenceFlags.Right);

var byBooleans = new PartialTriplet<int>(
    main: 10,
    left: 20,
    right: 30,
    hasMain: true,
    hasLeft: false,
    hasRight: true);

bool samePresence = byFlags.Presence == byBooleans.Presence; // true

if (byFlags.HasRight)
{
    int value = byFlags.Right;
}
```

Частичное значение также можно создать из полного аналога и маски наличия. Конструкторы сохраняют
переданные значения и флаги без изменений: они не отклоняют неизвестные биты перечисления, не
очищают содержимое отсутствующих позиций и не проверяют отношения между позициями. Используйте
только объявленные флаги и поддерживайте соответствие маски смыслу данных.

У каждого частичного типа есть две формы деконструкции: одна возвращает сохранённые значения,
другая дополнительно возвращает `Presence`. Методы `ToPair()`, `ToTriplet()` и `ToSeptuplet()`
помещают всё сохранённое содержимое в полное значение и намеренно отбрасывают маску. Они не
заполняют, не фильтруют и не проверяют отсутствующие позиции, поэтому преобразуйте значение
только после собственной обработки отсутствия.

У стандартного значения любой частичной структуры `Presence == None`, а во всех позициях хранится
`default(T)`.

## Разделение хроматического и геометрического порядка

<xref:Akeldov.Math.Hexes.Topology.Triplet`1> использует геометрический порядок `Main`, `Left`,
`Right`. <xref:Akeldov.Math.Hexes.Topology.ChromaticTriplet`1> вместо этого использует `Index0`,
`Index1`, `Index2`: каждая позиция относится к одному из трёх хроматических классов независимо от
того, из какой геометрической позиции получено значение.

Такая перестановка позволяет хроматическим барицентрическим растрам предоставлять устойчивое
соответствие между классом и весом. Частичный аналог хранит
`ChromaticTripletPresenceFlags`: вес гекса за пределами конечной карты недоступен, хотя сама
хроматическая позиция остаётся определённой.

```csharp
using Akeldov.Math.Hexes.Topology;

var weights = new PartialChromaticTriplet<float>(
    index0: 0.25f,
    index1: 0f,
    index2: 0.75f,
    hasIndex0: true,
    hasIndex1: false,
    hasIndex2: true);

float presentWeight = weights.HasIndex2 ? weights.Index2 : 0f;
```

Не считайте `Index0` эквивалентом `Main`, `Index1` — `Left`, а `Index2` — `Right`. Преобразовывать
или переставлять значения должна только операция, которая знает хроматический класс каждого
участвующего гекса.

## Предварительное вычисление окрестностей гексов

Две карты только для чтения заранее вычисляют семёрку для каждой ячейки топологии:

| Карта | Значение одного гекса | Поведение на границе |
|---|---|---|
| <xref:Akeldov.Math.Hexes.Topology.IndexSeptupletMap> | `Septuplet<VectorXYInt>` | Сохраняет шесть логических индексов соседей, включая индексы вне границ |
| <xref:Akeldov.Math.Hexes.Topology.IndexPartialSeptupletMap> | `PartialSeptuplet<VectorXYInt>` | Сохраняет те же логические индексы и снимает флаги соседей вне топологии |

Каждую карту можно создать из топологии или
<xref:Akeldov.Math.Hexes.Geometry.HexMapGeometry>. Перегрузка с топологией создаёт геометрию с
единичным радиусом; перегрузка с геометрией сохраняет её начало и радиус, чтобы карту окрестностей
можно было использовать и в операциях с пространственными картами. Сами окрестности зависят
только от разрешения и раскладки.

`IndexPartialSeptupletMap` также предоставляет вспомогательные свойства `Width`, `Height` и
`Count`. Для `IndexSeptupletMap` те же размеры и число ячеек доступны через `Topology`.

Различие хорошо видно на карте `1 x 1`:

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Topology;
using Akeldov.Math.Spatial2D;

var topology = new HexMapTopology(1, 1, Layout.OddR);

var completeMap = new IndexSeptupletMap(topology);
Septuplet<VectorXYInt> complete = completeMap[VectorXYInt.Zero];

// complete.Main      == ( 0,  0)
// complete.Adjacent0 == ( 1,  0)
// complete.Adjacent1 == ( 0,  1)
// complete.Adjacent2 == (-1,  1)
// complete.Adjacent3 == (-1,  0)
// complete.Adjacent4 == (-1, -1)
// complete.Adjacent5 == ( 0, -1)

var partialMap = new IndexPartialSeptupletMap(topology);
PartialSeptuplet<VectorXYInt> partial = partialMap[VectorXYInt.Zero];

// partial хранит те же семь координат.
// partial.Presence == SeptupletPresenceFlags.Main
```

При любом допустимом обращении к ячейке карты позиция `Main` присутствует в частичной карте.
`AdjacentN` присутствует строго тогда, когда сосед удовлетворяет условиям
`0 <= X < Width` и `0 <= Y < Height`. Порядок соседей совпадает у полной и частичной карт и при
любой раскладке соответствует номеру `HexEdge`.

Проверяйте флаги перед обращением к другой ограниченной карте:

```csharp
var costs = new HexMap<int>(topology);
var neighborhood = partialMap[VectorXYInt.Zero];

int total = costs[neighborhood.Main];

if (neighborhood.HasAdjacent0)
    total += costs[neighborhood.Adjacent0];

// Выполните такую же проверку для Adjacent1–Adjacent5.
```

Специализированные карты владеют своими заранее вычисленными массивами и не предоставляют
сеттеры значений. Индексатор карты с `VectorXYInt` проверяет обе координаты и выбрасывает
`IndexOutOfRangeException` за пределами топологии. Целочисленный индексатор использует
построчный порядок от нуля и подчиняется правилам границ массива. Пустая топология допустима,
но обратиться по индексу к её несуществующей ячейке нельзя. При создании из геометрии
неконечное начало либо неконечный или неположительный радиус приводят к
`ArgumentOutOfRangeException`; размеры и раскладку проверяет сама топология.

## Выборка окрестностей в растр

Растры индексов отвечают на другой вопрос: какие гексы исходной сетки участвуют в точке,
расположенной в центре каждой ячейки растра? У растра есть собственные разрешение и геометрия в
мировом пространстве; координаты его ячейки не являются индексами карты гексов.

| Растр | Сохранённое значение | Выбор в каждой точке |
|---|---|---|
| <xref:Akeldov.Math.Hexes.Topology.IndexTripletRaster> | `Triplet<VectorXYInt>` | Содержащий точку гекс в `Main` и два соседа с общей ближайшей вершиной в `Left` и `Right` |
| <xref:Akeldov.Math.Hexes.Topology.IndexPartialTripletRaster> | `PartialTriplet<VectorXYInt>` | Те же три позиции, независимо отмеченные при нахождении внутри исходной топологии |
| <xref:Akeldov.Math.Hexes.Topology.IndexSeptupletRaster> | `Septuplet<VectorXYInt>` | Содержащий точку гекс в `Main` и все шесть соседей по рёбрам |
| <xref:Akeldov.Math.Hexes.Topology.IndexPartialSeptupletRaster> | `PartialSeptuplet<VectorXYInt>` | Содержащий точку гекс и его внутренние соседи, но только когда `Main` входит в исходную топологию |

Полные растры используют модель бесконечной сетки. Выборка за пределами конечной исходной карты
разрешена и всё равно даёт логические индексы гексов. Частичные растры сравнивают эти индексы с
исходной топологией, но по-разному заполняют содержимое отсутствующих позиций:

- `IndexPartialTripletRaster` независимо проверяет `Main`, `Left` и `Right` и сохраняет
  `default(VectorXYInt)` в каждой отсутствующей позиции. У точки с `Main` вне карты всё ещё может
  присутствовать `Left` или `Right`.
- `IndexPartialSeptupletRaster` сохраняет вычисленные логические координаты даже в отсутствующих
  позициях. Если `Main` находится вне карты, все флаги сняты; если `Main` внутри, флаг каждого
  соседа отражает его попадание в границы.

Именно поэтому переносимый код потребителя должен считать источником истины маску, а не
сохранённую координату любого частичного семейства.

Каждый растр может получить стандартную геометрию выборки из
`HexMapGeometry.ToRasterGeometry(1f)` либо принять явную `RasterGeometry`. При создании оба
размера исходной карты и обе компоненты разрешения растра должны быть положительными. Иначе
выбрасывается `ArgumentOutOfRangeException`, а при переполнении проверяемого произведения размеров
растра — `OverflowException`.

Индексатор растра с `VectorXYInt` проверяет обе координаты относительно разрешения растра и
выбрасывает `IndexOutOfRangeException` за его пределами. Плоские целочисленные индексы используют
построчный порядок. Перегрузка `[x, y]` вычисляет плоский индекс без отдельной проверки каждой
компоненты, поэтому недопустимая пара может обратиться к другой строке или привести к исключению.
Перед её использованием проверьте обе координаты.

Метод `TryGetValue` есть только у растров индексных троек:

- `IndexTripletRaster.TryGetValue` возвращает `false`, только если запрошенная координата лежит
  вне растра; полученные индексы гексов всё равно могут находиться за пределами исходной карты.
- `IndexPartialTripletRaster.TryGetValue` также возвращает `false` для ячейки внутри растра, если
  её `Presence` равен `None`. В остальных случаях метод возвращает частичную тройку и `true`.

У растров семёрок в этой версии есть индексаторы, но нет метода `TryGetValue`.

## Неизменяемость и владение

Все полные и частичные контейнеры окрестностей — структуры `readonly struct` со свойствами только
для чтения. При передаче копируется их фиксированный набор полей, и изменение одной переменной не
может заменить поля другой копии. Это структурная, а не глубокая неизменяемость: если `T` —
ссылочный изменяемый тип, сам объект по ссылке всё ещё можно изменить.

Специализированные карты и растры индексов являются классами, но владеют внутренним заранее
вычисленным хранилищем и предоставляют его только через индексаторы для чтения. Каждый запрос
возвращает структуру окрестности по значению; вызывающий код не может заменить элемент
внутреннего массива. Пользовательский массив, последующее изменение которого повлияло бы на эти
таблицы поиска, конструкторам не передаётся.

Конструкторы универсальных контейнеров окрестностей не проверяют карту, геометрию, содержимое или
флаги. Выбор позиций и отсечение по границе выполняются только картой или растром, создающими
окрестность. Храните вместе с данными исходные топологию, раскладку и геометрию и никогда не
выводите наличие позиции только из её содержимого.

Далее см. [«Карты»](maps.md) для общего хранения значений ячеек и [«Растры»](rasters.md) для всех
семейств растров выборки.
