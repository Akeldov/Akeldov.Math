# Сохранение и загрузка карт

Hexes 0.6.0 добавляет бинарную сериализацию логических, целочисленных и вещественных карт,
включая пространственные варианты. Чтение создаёт изменяемую карту с независимым хранилищем.

## Сохранение пространственной карты в файл

```csharp
using Akeldov.Math.Hexes;
using Akeldov.Math.Hexes.Geometry;
using Akeldov.Math.Spatial2D;

var geometry = new HexMapGeometry(
    new HexMapTopology(2, 2, Layout.EvenQ), new VectorXY(-10f, 20f), radius: 2f);
var map = new SpatialFloatHexMap(geometry, new[] { 1.5f, -2.25f, 0f, float.NaN });

HexMapFile.Write("terrain.hmap", map);
SpatialFloatHexMap restored = HexMapFile.ReadSpatialFloatHexMap(
    "terrain.hmap", maxCellCount: 1_000_000);
```

Поддерживаются абсолютные и относительные пути. Относительный путь считается от текущей
рабочей директории процесса. Родительский каталог должен существовать. Запись создаёт или
перезаписывает файл; она не атомарна, поэтому ошибка после открытия может оставить неполную
запись. Файлы закрываются при успехе и при ошибке. Файловые методы читают первую запись и
игнорируют последующие данные.

## Выбор типа карты

Все шесть методов записи называются `Write`. Перегрузка выбирается по типу аргумента
на этапе компиляции. Конкретный пространственный тип и `ISpatialHexMap<T>` сохраняют
топологию, начало координат, радиус и значения. Переменная `IHexMap<T>` выбирает запись
только топологии и значений, даже если объект является пространственной картой.

| Тип значений | Чтение обычной карты | Чтение пространственной карты |
|---|---|---|
| `bool` | `ReadBoolHexMap` | `ReadSpatialBoolHexMap` |
| `int` | `ReadIntHexMap` | `ReadSpatialIntHexMap` |
| `float` | `ReadFloatHexMap` | `ReadSpatialFloatHexMap` |

Эти методы доступны у `HexMapFile` и `BinaryReader`. Метод чтения должен соответствовать
записанному виду карты и типу значений. Чтение не выполняет неявных преобразований типов
и не отбрасывает геометрию. Сериализация произвольных типов значений `HexMap<T>` не предоставляется.

## Работа с потоком

```csharp
using System.IO;
using System.Text;
using Akeldov.Math.Hexes;

var mask = new BoolHexMap(new HexMapTopology(2, 1, Layout.OddR), new[] { true, false });
using var stream = new MemoryStream();
using var writer = new BinaryWriter(stream, Encoding.UTF8, leaveOpen: true);
writer.Write(mask);
writer.Flush();
stream.Position = 0;
using var reader = new BinaryReader(stream, Encoding.UTF8, leaveOpen: true);
BoolHexMap restored = reader.ReadBoolHexMap(maxCellCount: 100);
```

Расширения оставляют reader, writer и поток открытыми. Сброс буфера и освобождение ресурсов
выполняет вызывающий код. Поддерживаются потоки без перемотки. Успешное чтение потребляет
ровно одну запись, поэтому в потоке можно хранить несколько карт и другие данные.
При ошибке позиция не восстанавливается. Исходная карта не должна меняться во время записи.

## Бинарный формат и ограничения

Каждая запись начинается с заголовка длиной 16 байт:

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 4 байта | ASCII `HMAP`, без префикса длины |
| 4 | 1 байт | Версия формата `1`, независимая от версии пакета |
| 5 | 1 байт | Вид карты: `0` — обычная, `1` — пространственная |
| 6 | 1 байт | Тип значений: `1` — Boolean, `2` — Int32, `3` — Single |
| 7 | 4 байта | Неотрицательная ширина, Int32 little-endian |
| 11 | 4 байта | Неотрицательная высота, Int32 little-endian |
| 15 | 1 байт | Раскладка: OddR=0, EvenR=1, OddQ=2, EvenQ=3 |

В пространственной записи по смещениям 16, 20 и 24 хранятся `Origin.X`, `Origin.Y`
и `Radius` в формате IEEE 754 binary32 little-endian. Origin задаёт центр нулевого гекса,
радиус измеряется от центра до вершины в единицах координатного пространства.
Апофема вычисляется при чтении.

Значения начинаются со смещения 16 или 28 и идут по строкам, сначала меняется X.
Boolean занимает один байт, строго 0 или 1. Int32 — четыре знаковых байта little-endian.
Single — четыре байта IEEE 754 binary32 с сохранением знака нуля, субнормальных значений,
бесконечностей и битов NaN. Пустые карты сохраняют оба размера и геометрию.
Сжатие, выравнивание и контрольная сумма отсутствуют.

`maxCellCount` по умолчанию равен `int.MaxValue`. Укажите подходящий приложению лимит,
чтобы отклонять чрезмерные выделения памяти. Нулевой лимит допускает только пустые карты.
Число ячеек и геометрия проверяются до выделения массива; для потоков с перемоткой также
проверяется наличие всех байтов значений.

Неверный заголовок, неподдерживаемый вид записи, неверный Boolean-байт, неконечное начало
координат, неположительный или неконечный радиус и превышение числа ячеек вызывают
`InvalidDataException`. Неполная запись вызывает `EndOfStreamException`.
Аргумент null вызывает `ArgumentNullException`, отрицательный лимит —
`ArgumentOutOfRangeException`. Исключения файловой системы передаются вызывающему коду.
