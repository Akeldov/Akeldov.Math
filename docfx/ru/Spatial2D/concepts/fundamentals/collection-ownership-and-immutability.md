# Владение коллекциями и неизменяемость

Контракты коллекций в Akeldov.Math.Spatial2D отвечают на два отдельных вопроса: что библиотека
делает с коллекцией, переданной в API, и какое владение получает вызывающий код при возврате
коллекции. Оба аспекта явно описываются типами коллекций и XML-документацией.

## Две группы ситуаций

| Направление | Основной вопрос | Возможные контракты |
|---|---|---|
| Коллекция на входе | Сохраняет ли библиотека что-либо после вызова? | Только использование, сохранение копии или сохранение исходной ссылки |
| Коллекция на выходе | Что представляет возвращённая коллекция? | Новый результат во владении вызывающего кода, read-only поверхность во владении библиотеки или прямой изменяемый доступ к существующему состоянию |

Контракты входа и выхода независимы. Например, API может скопировать входную коллекцию в своё
состояние, а затем предоставить эту копию через `IReadOnlyList<T>`.

## Коллекция на входе

Передача коллекции в метод или конструктор сама по себе не означает передачу владения.
Документация API указывает, какой из трёх вариантов применяется.

### Использована только во время вызова

Библиотека читает или перебирает коллекцию для выполнения операции и не удерживает её после
возврата из вызова. Вызывающий код остаётся единственным владельцем и может затем повторно
использовать или изменять коллекцию.

Не изменяйте заимствованную входную коллекцию, пока операция ещё выполняется, если API явно не
поддерживает конкурентную модификацию. В документации параметра этот случай обозначается как
использование только для текущей операции без удержания ссылки.

### Копия сохранена во владении библиотеки

Библиотека создаёт структурную копию и сохраняет её как собственное состояние. Исходная
коллекция остаётся во владении вызывающего кода, а её последующие структурные изменения не
влияют на копию библиотеки.

<xref:Akeldov.Math.Spatial2D.Curves.BezierCurve> применяет этот контракт к контрольным точкам:

```csharp
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Curves;

var input = new[]
{
    new PointXY(0f, 0f),
    new PointXY(1f, 2f),
    new PointXY(3f, 0f)
};

var curve = new BezierCurve(input);
input[1] = new PointXY(100f, 100f);

PointXY retained = curve.ControlPoints[1]; // По-прежнему (1, 2)
```

Это владение копией, а не исходной коллекцией. Если явно не указано иное, структурная копия
является поверхностной: элементы ссылочных типов всё ещё могут быть общими.

### Исходная ссылка сохранена: агрегация

Библиотека сохраняет ссылку на коллекцию, переданную вызывающим кодом. Структурная копия не
создаётся, поэтому вызывающий код и библиотека совместно используют одну коллекцию. Изменения
через одну ссылку видны через другую.

`Raster<TValue>` агрегирует массив значений, переданный конструктору:

```csharp
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Rasterization;

var values = new[]
{
    1, 2,
    3, 4
};

var raster = new Raster<int>(new VectorXYInt(2, 2), values);

values[0] = 10;
int throughRaster = raster[0, 0]; // 10
```

Агрегация позволяет избежать копирования, но связывает время жизни и изменения. Вызывающий код
не должен нарушать документированные инварианты и обязан согласовывать конкурентный доступ.
Документация API явно сообщает, что вход сохраняется как часть состояния.

Сам тип параметра не различает эти случаи. Входной `IReadOnlyList<T>` может быть только
использован, скопирован или сохранён как тот же объект.

## Коллекция на выходе

Возвращаемая коллекция следует одному из трёх контрактов владения. Её публичный тип служит
важным сигналом, но детали, которые невозможно выразить типом, указываются в XML-документации.

### Новый результат во владении вызывающего кода

Новый массив или `List<T>`, возвращённый как результат вычисления, является `CallerOwned`.
Библиотека не удерживает эту коллекцию, а вызывающий код может фильтровать, дополнять,
переставлять и повторно использовать её. XML-документация указывает, что результат новый,
изменяемый и принадлежит вызывающему коду.

Один из примеров — пересечения с лучом:

```csharp
using System.Collections.Generic;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Curves;

var circle = new Circle(new PointXY(0f, 0f), 5f);
var ray = new Ray(new PointXY(-10f, 0f));

List<PointXY> intersections = circle.GetRayIntersections(ray);

intersections.RemoveAll(point => point.X < 0f);
intersections.Add(new PointXY(20f, 0f));
```

Изменение этого списка не меняет окружность и последующие результаты поиска пересечений.
Владение вызывающего кода относится к структуре коллекции и не означает глубокого копирования
элементов ссылочных типов.

### Read-only поверхность во владении библиотеки

`IReadOnlyCollection<T>` и `IReadOnlyList<T>` обозначают выходной контракт `LibraryOwned`.
Коллекция представляет состояние библиотеки или семантический результат, структуру которого
вызывающему коду не следует изменять через возвращённую ссылку.

Есть два важных варианта внутреннего устройства:

- библиотека скопировала исходную коллекцию и возвращает read-only поверхность над своей
  копией, как `BezierCurve.ControlPoints`;
- библиотека сохранила исходную коллекцию или возвращает существующую коллекцию без изменений
  через read-only интерфейс, поэтому другая ссылка всё ещё может позволять её изменить.

На границе выхода оба варианта выглядят как доступ только для чтения. Документация члена
указывает, является внутренняя коллекция копией или оригиналом. `LibraryOwned` описывает
публичный контракт изменения, а не того, кто создал внутренний объект и имеет ли библиотека
исключительный доступ к нему.

Не приводите read-only результат к изменяемому типу времени выполнения ради его модификации.
Конкретный тип не входит в контракт, а обход интерфейса может нарушить инварианты результата или
состояния.

### Прямой изменяемый доступ к существующему состоянию

В редких API, ориентированных на производительность, свойство напрямую возвращает существующий
`List<T>` или массив. Это не новый результат во владении вызывающего кода, а совместный
изменяемый доступ к состоянию библиотеки. API явно указывает, что возвращена удерживаемая
коллекция и библиотека наблюдает сделанные изменения.

`Raster<TValue>.Values` возвращает сам удерживаемый массив:

```csharp
raster.Values[3] = 40;
int throughIndexer = raster[1, 1]; // 40
```

Такой контракт уместен, когда изменение элементов предусмотрено и не нарушает структурные
инварианты коллекции. Длину массива растра изменить нельзя, поэтому вызывающий код может
заменять значения ячеек, не нарушая соответствие разрешения количеству ячеек. Преимущество —
прямой массовый доступ без ещё одной полной копии растра; цена — общее изменяемое состояние и
необходимость самостоятельно синхронизировать доступ.

## Read-only не означает неизменяемость

`IReadOnlyCollection<T>` и `IReadOnlyList<T>` запрещают изменение только через эти интерфейсы.
Они не гарантируют:

- неизменяемую внутреннюю коллекцию;
- создание защитной копии;
- отсутствие другой изменяемой ссылки;
- неизменяемость элементов ссылочного типа;
- глубокое копирование состояния элементов.

Рассматривайте структуру коллекции и состояние элементов как разные аспекты. Коллекция во
владении библиотеки может сохранять количество и порядок, пока свойства изменяемого элемента
меняются.

Основные координатные и геометрические значения, например `PointXY` и `VectorXY`, обычно
являются неизменяемыми типами значений. Присваивание копирует само значение, но помещение таких
значений в read-only коллекцию добавляет отдельный контракт на добавление, удаление, замену и
перестановку элементов.

## Создание копии для изоляции

Создавайте копию на своей границе, если:

- заимствованный или агрегированный вход не должен отражать последующие изменения;
- read-only выход нужен как независимый снимок;
- прямое изменяемое состояние требуется редактировать без влияния на библиотеку;
- состояние элементов также необходимо изолировать от общих объектов ссылочного типа.

Для `IReadOnlyCollection<T>` используйте подходящий конструктор коллекции или операцию LINQ.
Для массива применяйте `Clone` или `Array.Copy`. Эти операции создают поверхностные копии; если
нужна глубокая изоляция, отдельно копируйте элементы.

Справочник API является источником истины для каждого члена. Ищите явные формулировки
«используется только во время вызова», «копируется в удерживаемое состояние», «удерживается как
состояние», «новый изменяемый результат во владении вызывающего кода», «read-only представление
скопированного состояния» и «прямой доступ к удерживаемому изменяемому состоянию».
