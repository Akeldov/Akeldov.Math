# Владение коллекциями и неизменяемость

Akeldov.Math.Spatial2D сообщает право на изменение коллекции и факт её сохранения в состоянии
библиотеки через типы коллекций и XML-документацию. Типы значений `PointXY`, `VectorXY` и
большинство небольших геометрических примитивов неизменяемы, но у коллекций и хранящихся в них
объектов могут быть отдельные правила изменяемости.

## Два типа владения

Вычисленные результаты-коллекции и структурные поверхности только для чтения используют два
контракта владения:

| Тип владения | Публичная форма | Контракт |
|---|---|---|
| Владение вызывающего кода | Возвращённый новый `List<T>` или массив | Вызывающий код получает новую изменяемую коллекцию, которую библиотека не удерживает |
| Владение библиотеки | Возвращённый `IReadOnlyList<T>` | Библиотека сохраняет структурное состояние или семантические инварианты; вызывающий код получает доступ только для чтения |

Эти контракты описывают коллекцию, возвращаемую через API. Копирование или удержание входной
коллекции конструктором либо методом — отдельный вопрос, рассмотренный ниже. API, который явно
предоставляет удерживаемое изменяемое хранилище, например `Raster<TValue>.Values`, разделяет
существующее состояние, а не возвращает новый результат и не передаёт владение.

## Владение вызывающего кода

Spatial2D возвращает `List<T>` или массивы для новых временных результатов, которые библиотека
не удерживает. Их XML-документация явно сообщает, что коллекция новая, изменяемая и принадлежит
вызывающему коду.

Один из примеров — пересечения с лучом:

```csharp
using System.Collections.Generic;
using Akeldov.Math.Spatial2D;
using Akeldov.Math.Spatial2D.Contours;
using Akeldov.Math.Spatial2D.Curves;

var circle = new Circle(new PointXY(0f, 0f), 5f);
var ray = new Ray(new PointXY(-10f, 0f));

List<PointXY> intersections = circle.GetRayIntersections(ray);

intersections.RemoveAll(point => point.X < 0f);
intersections.Add(new PointXY(20f, 0f));
```

Изменение этого списка не меняет окружность и не влияет на последующие вызовы поиска
пересечений. Тот же контракт владения вызывающим кодом используется для результатов отсечения,
выборок Пуассона, сегментов аппроксимации кривых, масштабированных копий элементов и производных
массивов сайтов Вороного.

Владение относится к структуре коллекции. Если API явно не обещает глубокую копию, элементы
ссылочных типов могут по-прежнему указывать на объекты, общие с входными данными или состоянием
библиотеки.

## Владение библиотеки

Владение библиотеки означает, что библиотека сохраняет контроль структурных изменений через
публичный контракт. `IReadOnlyList<T>` применяется, когда порядок, количество, смежность или
другой инвариант входит в сохранённое состояние либо семантический результат алгоритма.
Например, последовательность контрольных точек определяет кривую Безье:

```csharp
using System.Collections.Generic;
using Akeldov.Math.Spatial2D.Curves;

var input = new[]
{
    new PointXY(0f, 0f),
    new PointXY(1f, 2f),
    new PointXY(3f, 0f)
};

var curve = new BezierCurve(input);
IReadOnlyList<PointXY> controlPoints = curve.ControlPoints;

PointXY middle = controlPoints[1]; // (1, 2)
```

<xref:Akeldov.Math.Spatial2D.Curves.BezierCurve> копирует входные точки и предоставляет
структурное представление этой копии только для чтения. Замена элемента в `input` после создания
не меняет кривую.

Списки кривых контура, контуры областей, элементы разбиения, источники влияния и уникальные
значения поля используют аналогичные поверхности только для чтения, когда их структура входит
в сохранённое состояние или семантический результат алгоритма.

Владение библиотеки описывает возвращаемую поверхность API, а не того, кто первоначально создал
внутреннюю коллекцию. Операция проверки может вернуть вход без изменений, не предоставляя через
контракт `IReadOnlyList<T>` право на структурную модификацию.

Не приводите возвращённый `IReadOnlyList<T>` к изменяемой реализации ради её модификации.
Конкретный тип времени выполнения не входит в контракт, а обход поверхности только для чтения
может нарушить инварианты, даже если приведение оказалось успешным.

### Только для чтения не означает глубокую неизменяемость

`IReadOnlyList<T>` запрещает изменение через этот интерфейс. Сам по себе он не гарантирует:

- использование неизменяемого типа для внутренней коллекции;
- создание библиотекой защитной копии;
- невозможность изменить внутреннюю коллекцию через другую ссылку;
- неизменяемость элементов ссылочного типа;
- рекурсивное копирование элементов при структурном копировании.

Spatial2D документирует более сильную гарантию там, где она существует. Например,
`BezierCurve` описывает контрольные точки как скопированное состояние, а вспомогательный метод
проверки может вернуть входной список без изменений, поскольку проверка не передаёт владение.

Рассматривайте неизменяемость коллекции и неизменяемость элементов как разные вопросы.
Стабильный список изменяемых объектов только для чтения может сохранять порядок и количество,
даже если свойства одного из объектов изменились.

## Копируемые и удерживаемые входы

Обработка входов не является третьим типом владения возвращаемой коллекцией. Некоторые API,
например `BezierCurve`, копируют входную коллекцию перед сохранением состояния. После этого
вызывающий код может изменить исходную коллекцию, не затронув созданный объект.

Другие API намеренно разделяют изменяемое хранилище. `Raster<TValue>` удерживает массив,
переданный конструктору, и возвращает его через `Values`. Массив и индексаторы растра обращаются
к одним ячейкам:

```csharp
using Akeldov.Math.Spatial2D.Rasterization;

var values = new[]
{
    1, 2,
    3, 4
};

var raster = new Raster<int>(new VectorXYInt(2, 2), values);

values[0] = 10;
int throughRaster = raster[0, 0]; // 10

raster[1, 1] = 40;
int throughArray = values[3]; // 40
```

Совместное использование позволяет избежать дополнительного копирования всего растра и даёт
прямой массовый доступ. Одновременно оно требует от вызывающего кода согласовывать изменения.
Растр не синхронизирует доступ, а ссылка, полученная через `Values`, не является снимком.

Если растр должен быть изолирован от последующих изменений исходных данных, скопируйте массив
до создания:

```csharp
var isolatedRaster = new Raster<int>(
    new VectorXYInt(2, 2),
    (int[])values.Clone());
```

Сам по себе параметр `IReadOnlyList<T>` не сообщает, будет ли вход скопирован, удержан или
использован только во время вызова. Если важны последующие изменения, прочитайте документацию
параметра и свойства.

## Неизменяемые типы значений

Основные значения координат и геометрии обычно объявлены как `readonly struct`. Их публичное
состояние нельзя изменить после создания, а присваивание копирует значение:

```csharp
var original = new VectorXY(2f, 3f);
VectorXY translated = original + new VectorXY(1f, -1f);

// original по-прежнему (2, 3), translated равен (3, 2).
```

Операции возвращают новые значения вместо изменения получателя. Это отличается от коллекции
только для чтения: значение вроде `VectorXY` неизменяемо само по себе, а
`IReadOnlyList<VectorXY>` дополнительно управляет возможностью добавлять, удалять, заменять и
переставлять векторы через эту ссылку на коллекцию.

`readonly struct` всё ещё может содержать ссылку на изменяемый объект, поэтому `readonly` не
является общим обещанием глубокой неизменяемости. Следуйте документированному контракту
конкретного типа.

## Когда создавать собственную копию

Создавайте копию на своей границе, если:

- нужен снимок, который не отражает последующие изменения в другом месте;
- требуется изменить результат только для чтения, не затрагивая его инварианты;
- изменяемое хранилище передаётся API, который документирует его удержание, но нужна изоляция;
- требуется владение, независимое от времени жизни или правил другого компонента.

Поверхностную изменяемую копию `IReadOnlyList<T>` можно создать через `new List<T>(source)`.
Для массива используйте `Clone`, `Array.Copy` или другую явную операцию копирования. Если `T` —
изменяемый ссылочный тип и изоляция должна охватывать состояние элементов, дополнительно
выполните подходящее глубокое копирование.

Справочник API является источником истины для каждого члена. Ищите формулировки «новый
изменяемый список во владении вызывающего кода», «структурное представление только для чтения»,
«скопировано в удерживаемое состояние», «удерживается как состояние» и «возвращается без
изменений».
